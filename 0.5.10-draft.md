# 0.5.10 draft — the armed puck survives a removal, the end brake, and a spent board's stock

User prompt for this round:

```
1

in some cases , probably when circle keep moving on the rim, there is no trajectory show and after throw ball just disappear. this cause with player and with bot. not often

2

in rare case possible end of game and then move circle to return zone.

3

i think slow brake of big rotated circle after end will be good. like 4sec for stop. probably it was implemented sometime before but now not.
```

## Reading of the prompt

- **(1) A missing ghost and a throw that does nothing is one bug, not two.** The ghost
  preview, the aim arrow and the throw all address the armed puck by its **board index**
  (`pending`). A puck removed by the simulation — a black hole, or a permanent hole — is
  swap-removed, which pulls the board's *last* puck into the freed slot. The armed puck is
  always the last one spawned, so it changes index while its seat still aims: the ghost then
  traces a sleeping statue (one sample, no line), and `throwPuck` writes into an entry the
  step loop never visits, so the ball neither moves nor scores and is reclaimed by the
  return rule at the handoff. "Not often" is exactly its rate: it needs a puck to leave the
  board *while the next seat aims*, which needs the previous turn to hand over with
  something still sliding (a rim rider, `handoffT` expiry).
- **(2) A ball came back after the game was over.** The return rule is what keeps a round
  alive — a ball returned inside a turn window is a throw the seat still has (`handOff`
  runs the rule before it picks the next seat). The end of a game also ran it, with
  `giveBack`, while the disk was still braking and its riders were still being shed: a puck
  that came to rest in the return zone after the last throw put a ball back into a stock no
  turn can spend, which reads as a game that should have continued and did not.
- **(3) The end of a game is a brake, and it is now 4 s.** `beginSettle` already ramps the
  motor to 0 over `cfg.settleTime`; it was 3 s, and the embedded minigame capped the option
  at 3 s with a 1.2 s default. Both surfaces now stop over 4 s.

## Decisions

- **The armed puck is tracked by uid, not by index.** `syncPending` compares
  `w.uid[pending]` with the uid captured when the puck was armed, re-finds it with
  `findPuckUid` when they differ, and re-sims the ghost (the puck that was in the way is
  gone). It is called at the top of `tick`, `beforeSteps`, `afterSteps` and `commitThrow`,
  so the frame cadence cannot see a stale index; the check is O(1) in the common case.
- **A spent board returns no balls.** The `settle -> scored` recycle still clears what the
  return rule claims (the zone is the board's rule and the final picture should show it),
  but it hands nothing back: there is no turn left to spend a ball, and a stock that grew
  there is what the prompt saw.
- **No revival after the last throw.** A ball returned *inside* a turn window already
  brings a seat back (that is `handOff`'s order); after the brake has started the game is
  over by definition — the score is final, the result card is up, and un-spinning the disk
  would undo a state the flow has no path back from.
- **The minigame's settle bounds follow the game's own default.** `MAX_SETTLE` is
  `BASE_CFG.settleTime` and the fallback is the same value, so a host that asks for nothing
  gets the same 4 s brake as the page, and may still ask for a shorter stop (0.25 s floor).

## Rejected

- **Rekeying the armed puck at every removal inside the physics.** `swapRemovePuck` has no
  business knowing which entity the game is aiming; the uid is already the identity the
  predictor follows, and the game flow is the only place that wants it.
- **Guarding the throw by position instead of identity.** Comparing the armed puck's
  coordinates with the launch spot would miss a puck that a neighbour nudged, and it would
  still not tell the ghost which entry to trace.
- **Making the last payout wait for the board to settle** so that a late return can revive
  the game. It reintroduces the stall `handoffT` exists to remove, on the throw where it
  costs the most.
