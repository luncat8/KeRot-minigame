# 0.7.1-plan — Zone editor: drag-to-tune the board, lazy panel, copy-as-preset

Planning-only artifact (no implementation yet). Subject: an in-page editor for the
board's significant zones and sizes — big disk, holes, return zones, pucks — that is
**lazy-loaded** (the base page never pays for it) and can be **dragged** directly on the
board, with a **copy-to-clipboard** button that emits a chat-ready preset the user can
hand an LLM to turn into a registered preset.

## draft

- possible to edit by press and drag every significant zone variables and sized including big-disk, holes, return zones radius, pucks, etc
- button to copy result to clipboard to be possible paste to chat and tell llm to make this as preset

## 0. Requirements

- **Lazy.** The editor is an entry button. Only on first open do we load its script and
  build the handle layer; closing it tears the layer down. `index.html` + `js/main.js`
  never load editor code on a normal visit, so the shipped page stays lightweight.
- **Drag-to-edit** the significant zone variables and sizes:
  - big disk — centre `(diskX, diskY)` and radius `diskR`;
  - black holes — centre `(x, y)` and radius `r` for each of `BLACK_HOLES[0..1]`;
  - return zone — its size/reach: for the wedge/fan it is a radius from the disk centre
    (`returnZone`/`advanceZone` are triangles apexed at the centre), for the field zones
    (`rounded`/`arcs`/`3-rounded`/`6-hemi`) it is the clear-ice gap (`ZONE_CUT_GAP`) plus
    the positions/radii the outline hugs (the disk and the holes);
  - pucks — `puckR` (radius), `ballsPerPlayer`, and the launch lane (`launchMinX..
    launchMaxX`, `launchY`);
  - disk — `omega`, plus the enumerated selectors `diskSchema`, `recycleMode`, `zoneStyle`,
    `holeStyle` (these are panel selects, not drags).
- **Live.** Dragging a handle mutates `CFG` in place; the renderer already redraws every
  frame and scoring + zone tests read `CFG`, so the change is instant and consistent.
- **Copy button.** Writes a compact, chat-ready preset descriptor to the clipboard — a URL
  query, a JSON setup, and a one-line human summary — so pasting it to an LLM and asking
  "make this a preset" reproduces the board. The emitted keys mirror `presets.js`
  `parseQuery` so the LLM (or a later tool) registers it without guessing.

## 1. Architecture / lazy loading

- New `js/zone-editor.js` (classic `<script>`, Node-guarded like the rest). On first open,
  inject `<script src="js/zone-editor.js">` once (guard double-load), then `init(Render,
  Game, CFG)`. A second click or `Esc` closes it.
- Handles are drawn on a **transparent overlay `<canvas>`** positioned exactly over the
  board canvas. DOM nodes for ~10 handles are fiddly and re-layout on resize; one overlay
  canvas with a handle list is simpler and keeps hit-testing in world space.
- A small lazy **side drawer** (reusing the settings-panel styling) lists the numeric
  fields with live values and hosts the enumerated selects + the copy button. It is built
  on open and removed on close.
- Editor mode is a flag in the UI: while active, board pointer events go to the editor
  (the aim/throw path is disabled) and the drawer is shown.

## 2. World↔screen mapping

`Render.toWorld(clientX, clientY)` is a linear board-fit — the whole board maps to the
canvas rect, no zoom/pan:

```
world.x = (clientX - rect.left) * cfg.boardW / rect.width   // same for y with boardH
```

The inverse (screen/client from world) is `rect.left + world.x * rect.width / cfg.boardW`.
The editor overlay shares the board canvas's CSS box, so it can place handles with this
one linear map. Listen for `resize` to refresh the cached `rect` (the renderer already
handles its own backing store; the editor only needs the screen rect + `boardW/boardH`).

## 3. Handles / editable parameters

Group A — **big disk**: one centre handle `(diskX, diskY)`; one rim handle whose distance
to the centre sets `diskR` (clamped so the disk stays inside the walls).

Group B — **black holes** (×2): a centre handle `(x, y)` and a rim handle setting `r`.

Group C — **return zone**:
- wedge/fan (`zones`/`advance`): a "reach" handle — radial distance of the zone's outer
  edge from the disk centre — clamped to the board. Apex stays the disk centre; the two
  sides stay along their fixed directions.
- field zones (`rounded`/`arcs`/`3-rounded`/`6-hemi`): the outline hugs the disk + holes
  with a gap, so the editable knobs are `ZONE_CUT_GAP` (a slider; the gap reads in cm) and
  the disk/holes themselves (Groups A/B). No raw vertices — the shape is derived.

Group D — **pucks**: a puck handle sets `puckR` (clamp `puckR < diskR`); the launch lane
edge handle sets `launchMinX..launchMaxX`; a `launchY` handle; `ballsPerPlayer` is a
drawer number.

Group E — **disk**: `omega` (drawer slider or a spin handle), and the enumerated selectors
`diskSchema`, `recycleMode`, `zoneStyle`, `holeStyle`, `maxThrows` (drawer).

"Every significant zone variable and sized" ⇒ cover A–E above.

## 4. Live mutation + validity

- Every edit writes `CFG` (the live object). `render.js`, `score.js` (`scoreRates`) and
  `rules.js` (`inReturnZone`/`zoneField`) all read `CFG`, so they update the same frame.
- **Rebuild dependent geometry.** The zone triangles `cfg.returnZone` / `cfg.advanceZone`
  (and `advanceZone.lx`+`lw`) are computed once at init; the editor needs a `rebuildZones(cfg)`
  helper that recomputes them from `diskR`, `boardW/H`, `launchX` — mirroring `fitBoard`'s
  math but without refitting the whole board. Call it on every disk/zone/hole/puck edit.
- **Clamp on drag, don't reject:** `diskR` < min distance to the walls; holes stay off the
  disk and clear of each other (keep the existing `modelGates` separation, just interactively
  clamped); `puckR < diskR`; launch lane within the board; `ZONE_CUT_GAP ≥` its floor.

## 5. Copy-to-clipboard (LLM preset)

The button writes three forms, joined, so the paste is self-explanatory:

```
Make a KeRot preset from this board:
url:  index.html?zones=rounded&holes=classic&schema=classic&omega=0.78&muk=0.03&mus=0.045&mass=4&balls=4&recycle=advance&vote=round&votemode=delta&seats=human,staller
json: {"zones":"rounded","holes":"classic","schema":"classic","omega":0.78,"muk":0.03,"mus":0.045,"mass":4,"balls":4,"recycle":"advance","vote":"round","votemode":"delta","seats":["human","staller"]}
summary: big disk r=0.80 @ (1.10,1.10); 2 black holes r=0.18 at (0.48,0.00),(0.48,2.20); return gap 6cm; pucks r=0.10 x4; omega 0.78
```

- The URL uses exactly the keys `parseQuery` accepts; it is already a valid preset link.
- The JSON is the same setup object `applyCfg` consumes, values rounded.
- Use `navigator.clipboard.writeText` with an `execCommand('copy')` fallback for `file://`.
- The descriptor intentionally mirrors `presets.js` so the LLM (or a later "add preset"
  tool) registers it with no guessing.

## 6. Open decisions (defaults chosen)

1. **Overlay canvas** for handles (vs DOM nodes) — simpler hit-testing, one resize listener.
2. **Field-zone editing exposes the gap + disk/holes**, not raw vertices (shape is derived).
3. **Drawer** reuses settings-panel styling; enumerated selectors live there, geometric
   ones are drags.
4. Optional **snap/grid** for disk/holes to keep symmetry — decide during build.
5. Closing the editor keeps the board as edited (it is live `CFG`); a reset returns to the
   preset. Decided: edits persist until reset, like the sliders today.

## 7. Validation

- `experiments/zone-edit.js` (headless): apply a scripted sequence of editor mutations to
  a `CFG` clone; assert `rebuildZones` ran, zone tests agree with the drawn shape (reuse
  `zone-shapes.js` checks), and the copied descriptor **round-trips** through `parseQuery`
  + `applyCfg` back to the same `CFG` values (the LLM-reproducibility guarantee).
- Manual: open editor, drag disk/holes/pucks, confirm live redraw and that scoring follows;
  copy; paste into chat; confirm the LLM preset reproduces the board.

## 8. Implementation sketch (when executed)

- `js/zone-editor.js`: lazy loader, handle model `{param, get, set, screenPos, hitTest}`,
  overlay draw + pointer drag loop, drawer build, `rebuildZones(cfg)`, `copyPreset(cfg)`.
- `index.html`: an "Edit board" button → lazy-inject the script, call `init(Render, Game,
  CFG)`; `Esc`/second click closes and tears down.
- `presets.js`: no change needed — every emitted key is already parsed; an optional
  `stringifySetup` helper is nice-to-have.
