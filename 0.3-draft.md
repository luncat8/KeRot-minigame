# 0.3 draft — GUI: fit-to-screen board, help drawer, default table

User prompt for this round:

```
game playeble. but need improve gui:

move h1 and p intro/help to panel that show on pointer near left side or on swipe touch.

make canvas not cause scroll bar but fit any screen.

make push button green.

default 1 human + 3 bots: balanced, hole, retriver

think is antialiasing easy and cheap at least to plucks borders
```

## Reading of the prompt

- **The rules text leaves the panel.** The title and the long intro paragraph become a
  drawer parked off the left edge: a pointer within 28 px of that edge opens it, moving
  away closes it. Touch has no hover, so the same gesture is a swipe in from the edge,
  and a `?` tab at the edge pins the drawer open (tap out on the board, × or Esc
  closes). The drawer is an overlay — the board keeps running underneath.
- **The board is fitted, not scaled by CSS.** The canvas takes the largest rect of the
  board's aspect that fits its box on *both* axes, so no window shape can make the page
  scroll: `body` is `overflow: hidden`, the board is a flex item that fits, and the side
  panel scrolls inside itself. Refits are bound to `resize`, `orientationchange`, a
  `ResizeObserver` on the board box (the panel's scrollbar changes it) and the visual
  viewport (a mobile URL bar changes it).
- **The push button is the primary action** and is now the only green control
  (`#27ae60` / `#2ecc71` on hover), a shade no other button uses.
- **Default table** is one human against the three profiles that differ the most:
  `balanced` (scorer), `blackhole` (attacker), `retriever` (recoverer). Seat 0 stays the
  human, so the first drag on the board is always the player's.
- **Antialiasing.** Canvas 2D antialiases every vector shape already — there is nothing
  to switch on, and it costs nothing. What is cheap and worth doing is the three things
  that actually make an edge look hard: supersampling (the device-pixel ratio was capped
  at 2; it is now 3, with a 6 Mpx budget so a huge window cannot ask for a backing store
  the frame loop could not fill), strokes that sit *inside* the shape they outline (the
  puck ring was centred on the fill edge, so half of it bled onto the board as a halo),
  and not clipping to a curve per frame (the disk sprite is now cut to the circle once
  at bake time — cheaper, and the rim is filtered by the rotation instead of cut by a
  clip path).
