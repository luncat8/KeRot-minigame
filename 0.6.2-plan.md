# 0.6.2 plan — free-floating scratches, worn hex decor, a stereo listener

## Goal

Three changes, all inside the 0.6 opt-in (one page, no new file, no dependency, no
cost on a plain board):

1. the big disk's radial decor lines get a random length and position — most touch
   neither the centre nor the rim;
2. a settings choice replaces them with a worn hexagonal etching — soft edges, some
   randomly missing;
3. the sound layer gains a listener ("mic head") and stereo panning, with settings
   for where it faces and how loud it is (default 1.3× the old fixed level).

## Architecture

- `js/fx-glass.js`
  - `bakeDiskTex()` reads the module's `decorMode`. `radial`: the 190 scratches get
    `a = r()·τ`, `r0 ∈ [0.04, 0.70]·R`, `len ∈ [0.05, 0.43]·R` — a free position and
    length each. `hex`: `bakeHexTex()` strokes a flat-top honeycomb at 192² — per
    cell, each of the 6 edges is skipped with p ≈ 1/3, so a shared edge lands bright
    (drawn from both cells), faint (one cell) or missing (neither) — and is drawn
    upscaled into the 512 sprite, which is the softness trick `softTex` already
    proved: no edge survives vector-sharp. `bakedDecor` records the mode; `set()`
    rebakes only the disk sprite when the mode flips.
  - The listener: `panFor(x, y, cfg)` → [−1, 1] is the source direction's component
    on the right-ear axis (facing rotated 90° clockwise, screen coords). Facing per
    `faceMode`: `launch` — centre → (launchX, launchY), the initial puck position;
    `up` — centre → −y; `bottom` — the mic moves to (diskX, boardH), facing up.
  - Every event sound routes through one `StereoPannerNode` (`out(a, pan)`), shared
    by the event's partials. Contacts pan by the puck (rail) or the pair midpoint;
    throws by the launch box; voids and recycles by the gone puck's last tracked
    position (two more tracker slots, `ppx/ppy`); the closing chime stays centred.
  - The ice hiss gets one panner on its chain, driven per frame by the
    speed-weighted mean pan of the sliding pucks — no allocation, scalars only.
  - `set(state)` takes the FX state object `{visual, sound, decor, face, vol}`;
    the master gain is `VOL · vol`, `vol` defaulted to 1.3.
- `js/fx.js` — the lazy controller's state gains `decor`/`face`/`vol` with the
  shipped defaults; `set()` merges them; `apply()` hands the whole state object to
  the add-on. Unchanged: one script injection, gesture-gated audio, no-op on plain.
- `js/presets.js` — `DECOR_MODES = [radial, hex]`, `FACE_MODES = [launch, up,
  bottom]`, `vol` range [0, 2]; `parseQuery` reads `decor`, `face`, `vol`; the
  `default` preset lists the shipped triplet so it stays "complete on purpose".
- `js/ui.js` — `opts` and `SHIPPED` gain the three keys; a decor select, a listener
  select and a volume slider sit under the presentation row; `syncFX()` pushes them
  through `FX.set`; `liveQuery()` lists them when they differ from shipped.
- `index.html` — the three controls, help text (glass section + URL key list).
- No renderer change: the decor lives in the glass disk sprite, so `games/kerot.js`
  needs no rebuild (it bundles the renderer but no FX code).

## Validation

- `node experiments/fx-smoke.js` — extended: panner on the hiss chain; volume
  scaling (0.5 → half, 1.3 → shipped); pan signs for left rail / right rail /
  facing-launch / bottom-edge listener; decor switch rebakes exactly the disk sprite
  (radial +1 canvas, hex +2), re-applying is a no-op; hex etching keeps most cell
  edges and skips some; the new URL keys parse.
- `node experiments/render-frames.js --glass [--decor=hex]` — real PNGs of both
  decors (its `GlassFX.set` call moves to the object signature).
- `node experiments/client-smoke.js`, `minigame-smoke.js`, `node
  tools/build-minigame.js --check` — untouched paths stay green.

## Rejected

- A PannerNode with distance models: a full 3-D node per one-shot event for a
  strictly 2-D stereo question; StereoPanner is the whole need.
- Deduping shared hex edges with a Set: a double-drawn edge at α ≈ 0.05 just reads
  as less worn — the per-cell skip gives bright/faint/missing variance for free.
- Panning by the view's screen centre instead of the board: the listener is a
  board-space idea and must survive `fitBoard` letterboxing.
