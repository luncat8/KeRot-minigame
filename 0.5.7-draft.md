# 0.5.7 draft — the play-again gesture and the result card

User prompt for this round:

```
at the end of game double click canvas start new game. add popup to show this.

then review game and fix other issues if found. not about bot ballance because it is slow to test.
```

## Reading of the prompt

- **"At the end of the game" is a state, not a feeling.** The board has one after the last
  throw: `settle` (the motor spins down and the last payouts land) and then `scored` (the
  result is final). The result — and the winner — only exists in `scored`, so that is where
  the card belongs; the gesture is live from `settle` on, because from the last throw on
  there is nothing left to play.
- **"Double click canvas" must also be a double tap.** The standalone page is played with a
  finger as much as with a mouse. A double click is two pointer-ups on the same spot inside
  the system's double-click time; a double tap is the same pair with a touch pointer type.
  One gesture handler over `pointerup` covers both, and a spent board has no other click
  action to collide with.
- **"Add a popup to show this" is the result card, not a modal.** It sits over the board,
  lets every pointer through (the board underneath is the button), names the winner and the
  final scores, and says the gesture. It is DOM, not canvas paint, so the text is real text
  for assistive tech and the same element restyles with the colour scheme.
- **"Fix other issues if found" — not bot balance.** Balance is measured by the experiments
  and is slow to judge; this round looks at the page's flow, input and chrome instead.

## Decisions

- **The board box is the card's coordinate space.** `#boardWrap` is `position: relative` in
  both layouts and `js/ui.js` pins `#result` to the canvas's own offset and size. In the fit
  view the canvas fills the box, in the side view it is letterboxed at the top: one rule
  covers both, and a resize re-pins it on the next panel tick (~5 Hz).
- **The card is shown by state, not by an event.** `UI.update` owns it: shown in `scored`,
  hidden otherwise, rewritten when the winner or a score changes (a seat can still be
  removed from a finished game). No new event plumbing between game and panel.
- **The gesture lives with the game flow.** `Game.bindInput` (the standalone page's input,
  not the shared pointer handler the Snowfall slot uses) installs a `pointerup` pair
  detector: two taps within 600 ms and 40 px deal a new game, only while the round is over.
  A slot that resolves a story match must not silently restart the board, so the shared
  `bindPointer` stays untouched.
- **A new game is live.** `reset()` clears the pause flag as well; a board dealt from the
  card or from `R` must not sit frozen under a label that still says Pause.
- **A tie is a tie.** Equal raw scores read as a draw (a solo board is its one seat's game);
  the winner's cell is what the HUD and the panel row light once the board is spent.
- **A focused control owns its keys.** Space and the arrow keys belong to whatever input,
  select or button has focus; the game reads them only from the board/page. And a paused
  board reads neither, so a stroke cannot be nudged or thrown from under a pause.

## Not in this round

- **The popup does not offer buttons.** The board itself is the button and the text says
  so; a second click target over the same gesture would be a second thing to explain.
- **The Snowfall slot gets no restart.** Its result is an answer to the story engine; a
  replay would answer twice. The slot keeps its own chrome and its own end state.
- **The end-of-game payout is not shortened.** `settleTime` still runs the disk down and the
  board still pays while it does; the card appears when that payout is final.
