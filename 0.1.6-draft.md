# 0.1.6 draft — seats: N players, 4 balls each, red-area scoring

User prompt for this round:

```
choose N players (dent need restart for easy test, just add new or remove)

each player has 4 balls and push 1 at his turn then turn of other player.

## score

start (player push Pucks)
end after 4sec
in this time range each turn we calculate and sum score:
player.score += dt* (area of red color on big_disk that  enclosed by a player's Pucks).
if color is 22,123,0 we get 22 as red component. note we have some gradient so color in every pixel is
different. do not be very precise, think how to optimize and calculate fast. no need to calculate
analytical integral between frames if this is slow, grid based also is ok. if all solutions are slow -
it is also ok to choose central + 6 samples on perimeter of Puck.

to display normalize to reasonable score range like 0...999 per game
```

## Reading of the prompt

- **Seats, not a pool.** Every player is a seat with his own 4 balls and his own score.
  Seats take turns in order; a turn is *one* push, then the next seat. The round is
  over when no seat has a ball left. The roster is edited live (add / remove) — no
  reset, so switching between 1 and 8 seats is one click while a game is running.
- **Score is a rate, integrated over the turn window.** The window opens when the
  seat pushes and closes `handoffT` = 4 s later (or earlier if the board settles —
  the handoff timer of 0.1.5 is already this rule). Inside the window every seat
  earns `dt · A_red(seat)`: the area of the big disk his pucks cover, weighted by the
  red component of the pixel painted there. All seats earn at once — the board is
  shared, so the game is "hold the red while the others try to take it".
- **Red component, literally.** `fieldColor()` paints the disk; the score density is
  its red channel, 0…255. It is monotone in the field value (55 at v = −1 → 245 at
  v = 0 → 255 at v = +1), so the cold lobes are what a player pays for, and nothing
  is more expensive than it looks on the board.
- **Cheap, not exact.** The area integral is the puck's own equal-area sample pattern
  (the same cells the friction integrates), one weight `πr²/N` per cell, and the red
  value comes from a grid baked once over the disk, so a cell costs two multiplies
  and a bilinear read instead of four `exp()`. Accuracy is measured (experiments/
  scoring.js), not assumed.
- **Display 0…999.** Raw score is `red·m²·s`, an arbitrary unit; the panel and the
  on-board HUD show `999 · score / ref`, where `ref` is what a seat would earn with
  all 4 balls parked on the reddest pixel for the average lifetime of a ball in a
  game of that size — so the number means the same thing for 2 seats and for 8.

Still in force from earlier drafts: stroke 0…3 m/s with shift precision, ω capped at
4.000 rad/s defaulting to `autoOmega()`, the 6-sector pucks, the ghost preview, the
two return rules and their on-disk exemption, continuous physics in every turn state,
and the 4 s handoff. A puck a return rule claims goes back to *its owner's* stock,
which is what "return to pool (reuse)" means now that the pool is per-seat.
