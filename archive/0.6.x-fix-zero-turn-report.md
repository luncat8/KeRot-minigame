
## "Players don't move" — closed

Recap of the investigation delivered above:

- **Root cause:** bots (and a human grab-ring tap) could commit a **zero-speed throw** — the puck sleeps on the launch spot in one step, the turn hands over instantly, and the launch-lane return rule reclaims the puck without it ever moving. That reads exactly as "the seat skipped its move / the puck went back to the start by itself".
- **Evidence:** 11 of 173 throws in the before-run were dead (`speed ≤ 0.06 m/s`, travel ≤ 6 mm, **all 11 returned without moving**); `random`/`retriever` picked dead strokes ~15–19% of the time; `bot-picks`' own boards held 5 dead picks.
- **Your earlier uid fix holds:** 0 stale-slot cases, 0 turns without a throw — different cause, now fixed.
- **Fix:** `CFG.vThrowMin = 0.30` — a throw must move the puck (thrown at the floor if aimed lower, refused if directionless); bots never rank or pick a dead stroke; aim/ghost/throw stay the same stroke everywhere (page, warp, minigame).
- **Verified:** after-run **156/156 throws ≥ 0.5 m/s, 0 no-move, 0 anomalies**; full suite green (client-smoke with 4 new regression checks, minigame-smoke, settings-revive, determinism, speed-vote, scoring, vote-rules, fx-smoke); `bot-picks` diff shows only the 5 dead-pick rows changed — the other 67 lines byte-identical.
