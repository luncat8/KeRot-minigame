**The draft's three questions, answered in the plan:**

1. **Own integrator vs Box2D/planck.js → own.** Everything the draft asks for is cheaper to do exactly than to coax out of an engine: swept circle time-of-impact (exact, no tunneling — engines only sweep against *static* bodies), friction against two surfaces at once weighted by contact-area, and the clean static criterion `ω²d ≤ μ_s g`. Plus zero dependencies, `file://` friendly, and headless node experiments for the same code. An engine only wins if the game later grows polygons/stacks/hundreds of bodies.

2. **Rotational impulse direction.** Lab frame only, never fictitious centrifugal terms: friction opposes the velocity *relative to the local disk surface*, `v_rel = v − ω·(−dy, +dx)`. Using `v` against the disk instead is the classic bug — pucks lose energy instead of being flung. Spin-up, outward spiral and ejection all fall out of that one term.

3. **"Pucks are round, so just compute the collision time."** Correct — it's one quadratic, resolved at the exact instant, zero overshoot.

**Correction to the draft's premise:** the 90 % rule `mω²d ≤ μ_s m g` **cancels mass**, and so does the throw (a stroke sets a velocity, not a force). Mass only matters for puck–puck exchange. So the rule is really a choice of `ω`; defaults are `μ_k=0.03, μ_s=0.045` (ice), `R=0.80 m`, and `ω = √(μ_s g / 0.9R) = 0.783 rad/s` → `d_hold = 0.9 R` exactly, with an "auto-ω (90 %)" button, a live `d_hold/R` readout, and a dashed eject ring.

**Other decisions baked in:** fixed `h = 1/480 s` accumulator with timestamped input events (frame-rate independence, incl. throw timing), Σ-of-blobs field over 4 rotating sources + bias (scores inside *and* outside the disk, so pucks flung out lose points), 3.6×2.2 m board, 8 pucks, settle phase that spins the disk down before scoring, baked low-res field textures rotated per frame, and typed-array state with zero hot-path allocations.
