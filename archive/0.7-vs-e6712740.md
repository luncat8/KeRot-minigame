# 0.7 vs e6712740 — design comparison

Both implementations answer the same design drafts (`archive/temp/`,
captions in `0.6.5-draft.md` on that lineage): new return-zone markings and
new black-hole shapes. They differ in how deep the change goes.

## The short version

| | this branch (0.7) | `e6712740` "new zone shapes" |
|---|---|---|
| zone options | `straight` · `wavy` · `arc` (`CFG.zoneStyle`, `?zone=`) | `hatch` · `wavy` · `rounded` · `arcs` (`zoneStyle`, `?zones=`) |
| hole options | `flush` · `rounded` · `hemis` (`CFG.holeShape`, `?hole=`) | `classic` · `rim` · `well` · `triangle` (`holeStyle`, `?holes=`) |
| score cards | — | `square` · `round` (`opts.cards`, `?cards=round`) |
| panel UI | two selects, one row at the top of the panel | two radio groups ("return zone shape", "black holes") + a "rounded score cards" checkbox |
| what changes | **mostly skins**: the zone rule tables are untouched | **rules, not skins**: the shapes *are* the rule regions |
| extra docs/tooling | `archive/0.7-plan.md`, `experiments/zone-hole-styles.js` (9 combos, pixel-diff vs baseline) | README "Field marking shapes", `archive/0.6.5-{plan,worklog}.md`, `experiments/zone-shapes.js`, `render-frames.js --zone/--holes/--cards` |

## Design-level differences

- **Zone geometry.** Ours only repaints the marking: the wedge/lane tables that
  scoring and the bots read never move; `straight`→`wavy` swaps the hatch fill,
  `arc` adds one big circular outline. The alternate rebuilds `rounded`/`arcs`
  from a smooth-min clearance field (`zoneField` in `js/rules.js`, traced with
  marching squares), so the zone's real boundary hugs the disk and the holes —
  the rule follows the drawing, and switching shapes invalidates the ghost
  trajectory because a differently-shaped void swallows other paths.
- **Hole geometry.** Ours: `flush` (wall-cut half-discs, shipped) and `hemis`
  (lit domes) keep the shipped capture; `rounded` is the one real geometry
  change — `holePositions` moves the voids in by `r` to full circles, and the
  zone marking is cut around them with a `ZONE_GAP` guard. The alternate keeps
  two round styles (`classic`/`rim`/`well` differ in reach ring and shading)
  but `triangle` changes capture itself (`holeGap`), matching the drafts'
  triangle hole that echoes the zone's side.
- **Score cards.** The original draft note says the rounded score cards of the
  rounded draft are part of the task; only the alternate shipped them
  (`cards=round` on the result card). This branch has no equivalent.
- **Cost.** Ours adds one Path2D per zone style and a gradient per dome — no
  rules/bot/physics impact beyond the moved `rounded` voids. The alternate pays
  for its shapes in `rules.js` (clearance field, marching-squares trace,
  per-frame geometry) and in bot-visible rule changes.
- **Surface area.** 3×3 combos with human labels here ("diagonal hatch",
  "big arc outline", "domes"), 4×4 + a page toggle there, plus a README
  section and a dedicated harness.

## What each has that the other lacks

- Alternate only: rounded/arcs true rule regions, triangle/well/rim holes,
  rounded score cards + its URL key, README section, render-frames shape flags.
- This branch only: the hemis dome look, the `ZONE_GAP` cut-out around
  `rounded` holes, top-of-panel selects, longer help prose, the 9-combo
  pixel-diff harness.
