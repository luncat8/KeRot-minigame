# 0.6 — optional glass presentation, shadows and ice/glass sound

Scope: the user asked for “better textures of game field and plucks” (pucks), shadows,
ice/glass sound effects, and whether that belongs in a separate HTML/CSS/render layer or
can stay “like a option in same html” without making the base version heavy. The full
prompt is kept in `0.6-draft.md`; the forkable architecture is in `0.6-plan.md`.

## Architecture

Kept one `index.html`. A second HTML would duplicate the whole game shell; a separate CSS
layer cannot follow the canvas transform, bake field/puck material, draw contact shadows,
or synthesise sound. The chosen split is a page-level opt-in:

- `js/fx.js` (2,677 bytes) is the only new boot-time script. It mirrors `fx`/`sfx` state,
  observes one world snapshot per frame, and injects the add-on once on the first glass
  visual or sound request. A plain/silent link creates no WebAudio context and fetches no
  add-on, image or audio file.
- `js/fx-glass.js` (19,177 bytes) is a local classic script, fetched on demand. It bakes
  fixed-size frost/floor, disk, grain, gloss and shadow canvases once, then draws cached
  sprites through renderer hooks. It also owns all procedural WebAudio synthesis.
- `js/render.js` gained five optional hook points (`setup`, `floor`, `disk`, `shadow`,
  `puck`) and `Render.attach(addon)`. `disk` runs in the rotated local frame; the others
  run in world coordinates. All `shadow` hooks are called before any puck body, so no
  shadow paints over a stone. A null skin leaves the shipped draw path unchanged apart
  from the hook checks, and each renderer instance can own its own skin.
- `js/main.js` passes `dt`, the world, the state name and the paused/planning flag to
  `FX.frame()` after fixed steps. No physics or game-flow callbacks were added: the sound
  observer uses preallocated typed arrays and per-uid state changes, leaving determinism
  and simulation untouched.
- The Snowfall single-script bundle is rebuilt because it carries `js/render.js`, but
  `fx.js`, `fx-glass.js`, WebAudio, presentation controls and page CSS are deliberately
  not bundle sources. `games/kerot.js` remains a plain classic script (177,563 bytes).

## Presentation and sound

- The glass option adds frosted floor grain, scratches, fissures, vignette, a translucent
  rotating disk overlay with etched rings, radial brushing, sheen and a rim bevel, puck
  grain/gloss/glint, a disk shadow, and two per-puck shadow layers. The disk's red/blue
  field remains the score map; overlays are translucent and never change scoring,
  bot aims, seat rings, puck numbers, gauges or labels.
- The first real-canvas glass render was too subtle. Alpha, grain, bevel and contact
  shadow strengths were tuned until `classic-classic-glass.png` and
  `kerot-rim6-glass.png` showed visible frost, rim relief, puck shadows and gloss while
  keeping the score paint readable.
- Sound is entirely procedural: one reusable noise buffer, a gain-controlled ice hiss,
  band-passed glass partials for contacts, dull rail taps, release swishes, low void
  sounds and a soft final chime. The `AudioContext` is created/resumed only on a user
  gesture. Sound is muted when off, paused, planning, or the document is hidden; the
  tracker stays current while silent so re-enabling cannot replay stale collisions.
- Controls are a `presentation` select and `ice / glass sound` checkbox. `fx=glass`,
  `sfx=1` and the `crystal` preset enable them; `default` restores plain/silent. Custom
  links emit only values that differ from the shipped state. Small
  `body[data-fx=glass]` CSS supplies outer chrome only.
- `README.md`, the in-page help and URL notes, and `docs/snowfall-integration.md` explain
  the option and the distribution boundary. `findings-pitfalls-skills.md` records the
  lazy-controller/no-op-hook pattern and the `fx=` vs `sfx=` whole-key regex pitfall.

## Validation

Headless and real-canvas, from the repo root unless noted:

- `node experiments/fx-smoke.js` — **OK** (lazy glass loader, baked canvas skins,
  procedural ice/glass audio). Covers single-context floor/disk hooks in both themes,
  WebAudio graph, sliding hiss, contact/void/throw/end sounds, silence and visibility
  mute.
- `node experiments/client-smoke.js` — **OK** (render + score + seats + ui smoke). New
  gates prove all five hooks are reachable once per frame/puck, `Render.attach(null)`
  restores the base path, the HTML loads only the tiny controller, build sources exclude
  the add-on, and `fx`/`sfx` URL, preset, link, control and body-state round-trips work.
  The first run exposed `includes('fx=')` matching inside `sfx=1`; fixed with
  `/(?:^|&)fx=/` style whole-parameter checks and recorded as a pitfall.
- `node tools/build-minigame.js && node tools/build-minigame.js --check` — rebuilt
  `games/kerot.js` from the changed renderer; bundle matches its sources.
- `node experiments/minigame-smoke.js` — **OK** (bundle, two-session isolation, live
  match, cleanup, saved and skip results; 197 frames).
- `determinism.js`, `settings-revive.js`, `speed-vote.js`, `zone-catch.js`, `scoring.js`,
  `spin.js`, `time-warp.js` and `vote-rules.js` — all gates **OK**. The generated
  `vote-rules` result from this validation run was removed afterward.
- `node --check` over every `js/`, `minigame/`, `tools/`, `experiments/` and generated
  bundle script; `git diff --check` — clean.
- `cd experiments/tools && npm install --no-audit --no-fund` installed
  `@napi-rs/canvas` for offscreen rendering. `node experiments/render-frames.js
  experiments/logs/frames` and `node experiments/render-frames.js --glass
  experiments/logs/frames` wrote 12 real 1798×1100 PNGs (plain and glass for
  classic/kerot × classic/circles/rim6). Glass PNGs were rerendered after tuning.
  These ignored log artifacts are not part of the shipped payload.

Real-browser audio playback and autoplay/visibility behavior remain unverified by the
headless WebAudio stub; that is the one acceptance check a person should do in a browser.

## Next step

Open `index.html` in a real browser (or a local static server), enable `crystal`, and
check that the first gesture unlocks ice/glass audio, tab hide/show mutes and resumes
cleanly, and live-switching `plain`/`glass` stays smooth on a phone-sized viewport. If
that is clean, the next optional round would add a volume control and a
`prefers-reduced-motion` default rather than another presentation file.
