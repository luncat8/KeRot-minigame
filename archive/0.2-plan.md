# 0.2 plan — rotation-aware bots, recovery, and black holes

## Scope

Build on the 0.1.6 seat/score model. Bots must evaluate a shared set of candidate strokes against the same game outcomes the player sees: red-area score accumulated while the disk rotates, stable scoring opportunity, returnable pucks and reserve stock, puck-loss risk, and enemy losses. Add recovery-focused, black-hole, and balanced bot profiles, plus a deterministic headless competition to compare them.

## Review of 0.1.6

Live removal of a seat drops that seat's pucks, but leaves larger `world.own[]` indices unchanged after `roster.splice()`. A remaining puck can then score into an undefined seat and throw. Reindex surviving puck ownership (and per-seat counters) after removal, and test removing a seat that already has scoring pucks on the board.

## Rules and model

- Predict the score rate throughout the simulated turn, not only at its final angle. Integrate samples in disk-local coordinates while `theta` advances; also report the final rate as a future scoring opportunity.
- Add two semicircular black-hole regions along the left-side map boundary, one above and one below the disk. A puck is captured when its center enters the hole plus its own radius; it is removed permanently and does not return to stock. Black holes are separate from the existing recyclable return zones.
- Count permanent losses by owner so prediction can distinguish risking one's own puck from eliminating an opponent's puck. Keep puck identities stable across swap-removal so the ghost/predictor follows the thrown puck when another puck is captured.
- Keep return policy authoritative: a puck counts as recoverable only if it would be sleeping inside the currently selected return zone when the turn ends. Recovery incentives increase as the acting seat's reserve runs low.

## Bot evaluation

Evaluate a common deterministic candidate set with strategy-specific weights. Candidate features are:

1. integrated change in the acting seat's red-area score during the predicted resolve;
2. the change in final score rate, valued as a future opportunity while the puck remains on the board;
3. opponent score denied;
4. own pucks newly recovered by the active return rule, weighted by reserve scarcity;
5. own pucks permanently lost and enemy pucks permanently lost;
6. a small seeded tie-break / exploration term for the random profile.

Provide `random`, `keeper`, `hunter`, `retriever`, `blackhole`, and `balanced` profiles. Every profile retains score and recovery incentives; the latter three express their preference through larger recovery, elimination, or balanced weights. Bias some candidates toward the rotating hot lobe, owned off-disk pucks, and enemy pucks near holes so strategic actions are sampled rather than left to chance.

## Implementation boundaries

- `js/cfg.js`: black-hole geometry.
- `js/physics.js`: stable puck IDs, owner-loss counters, continuous-step capture and a shared swap-remove helper.
- `js/rules.js`: owner reindexing and a query for whether a puck would recycle.
- `js/score.js`: one-pass per-seat score rates for predictor sampling.
- `js/predict.js`: rotation-aware score integration, final opportunity/recovery/loss metrics, and candidate identity tracking.
- `js/bots.js`, `js/game.js`, `js/players.js`: shared weighted evaluation, new bot profiles, and roster context.
- `js/render.js`, `index.html`: visible black-hole zones and updated strategy descriptions.
- `experiments/bot-strategies.js`: seeded headless evaluation and regression gates; keep generated output separate from the existing 0.1.6 competition result.

## Validation

- Extend the browser-layer smoke for live owner reindexing, rendering, roster options, and a complete bot game.
- Add deterministic gates for black-hole capture/permanent loss, puck identity after swap-remove, zone-dependent recovery, rotation-aware prediction, and finite valid actions from every profile.
- Run the bot comparison across multiple rotated seats and fixed seeds. Review score, recovery/loss counts, win rates, and runtime before setting the balanced profile weights.
- Re-run the existing physics, scoring, zone, settings, and smoke experiments. Scan classic scripts for top-level name collisions.
