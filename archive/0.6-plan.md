# 0.6 plan — optional glass presentation without a heavy base

## Goal

Add a richer game-field and puck material, visible shadows, and ice/glass sound
effects while keeping the shipped page and the Snowfall single-file bundle light.
The base board stays the default; the richer look is an option in the same HTML.

## Architecture

- Keep one `index.html`. Do not fork the page into a second HTML file, do not move
  the board into a separate stylesheet, and do not replace the canvas renderer.
- Add a tiny boot controller, `js/fx.js`, whose only heavy action is to inject
  `js/fx-glass.js` on the first request for glass visuals or sound. A plain link
  fetches no add-on, no image, no audio file and no WebAudio graph.
- Put the optional presentation in `js/fx-glass.js`: baked canvas sprites, shadow
  drawing, and procedural WebAudio synthesis. It is a classic script, Node-safe at
  parse time, and needs no build step or third-party runtime.
- Add five no-op hook points to `js/render.js`: `setup`, `floor`, `disk`, `shadow`,
  `puck`. `disk` runs in the disk's rotated local frame; the others run in world
  coordinates. A null skin leaves the base draw path byte-for-byte intact apart
  from the hook checks. Every renderer instance can own its own skin.
- Pass one world observation per frame from `js/main.js` to the optional sound
  layer. Do not add event callbacks to physics or game flow: sounds are derived
  from typed-array state changes, so simulation and determinism are untouched.

## Presentation

- Bake once: frosty floor grain, scratches and vignette; a transparent rotating
  disk overlay with etched rings, brushed radial grain, a light streak and a rim
  bevel; puck grain, a fixed specular gloss, and a soft radial shadow sprite.
- Draw only cached sprites and a few arcs per puck. No gradients, buffers, object
  literals or string concatenation in the frame loop.
- Keep the disk's red/blue field as the score map. Overlays are translucent and
  decorative; scoring, bot aims, seat rings, puck numbers, gauges and labels stay
  in the shipped renderer. Tune alpha separately for the classic and kerot themes.
- Shadows: one soft disk shadow under the zones, and two per-puck layers (soft plus
  contact) drawn before any puck body so a shadow never paints over a stone.
- Page CSS stays small: a `body[data-fx=glass]` outer glow and frosted result card.
  The heavy visual detail is canvas, where it follows the board transform.

## Sound

- Synthesise everything with WebAudio: one reusable noise buffer, a looping
  band-passed ice hiss whose gain follows total sliding speed, short glass partials
  for puck contacts, dull rail taps, release swishes, low void sounds and a soft
  final chime. No audio assets or network requests.
- Create/resume the audio context on a user gesture. Mute on sound-off, pause,
  planning, and document hide; keep the world tracker current while silent so
  re-enabling sound cannot replay stale collisions.
- Detect contacts from per-uid velocity jumps plus wall/puck proximity; detect
  black holes from `ownerLosses`, throws from `thrown`, and the end from the game
  state. Rate-limit clinks so one collision between two pucks is one sound.

## Controls and links

- Add a `presentation` select (`plain` / `glass`) and an `ice / glass sound`
  checkbox to the settings panel. Both are page state, not `CFG`.
- Add `fx` and `sfx` URL keys, include them in custom links only when they differ
  from the shipped state, and add a `crystal` preset that turns both on. The
  `default` preset restores plain and silent.
- `UI.syncFX()` is the single place that mirrors controls into `UI.opts()`, sets
  `body.dataset.fx`, and calls `FX.set()`. Boot links, presets and manual changes
  all go through it.

## Distribution boundary

- `games/kerot.js` is rebuilt because it carries `js/render.js`, but it must not
  include `fx.js`, `fx-glass.js`, WebAudio, the presentation controls or the page
  CSS. The story-page artifact stays a plain single classic script.
- Document the option in `README.md`, the in-page help, and the Snowfall integration
  notes. The optional layer is a page feature, not part of the game contract.

## Validation

- `node experiments/client-smoke.js`: renderer hook reachability/detachment,
  static script layout, UI controls, URL/preset round-trip and body attribute.
- `node experiments/fx-smoke.js`: lazy injection, baked sprite hooks in both themes,
  WebAudio graph, contact/void/throw/end sounds, silence and visibility mutes.
- `node tools/build-minigame.js && node tools/build-minigame.js --check`.
- `node experiments/minigame-smoke.js`, `node experiments/determinism.js`, the
  physics/scoring experiments, `node --check` over changed scripts, `git diff --check`.
- `node experiments/render-frames.js [outDir]` and `--glass [outDir]` for real
  before/after PNGs through `@napi-rs/canvas`.

## Rejected

- A second HTML page or a separate presentation CSS layer: duplicate markup,
  another file to keep in sync, and no access to the canvas transform.
- A static `<script>` for the heavy add-on: every plain page would download it.
- Raster image or audio files: larger payload, extra requests, harder theme tuning.
- Physics event hooks inside `stepWorld`: they would touch the deterministic hot
  path for a purely presentational feature.
- Bundling the add-on into the Snowfall game: the story slot has no presentation
  controls and its single-file payload is a deliberate contract.
