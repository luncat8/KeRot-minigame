# 0.7.3 worklog — On-map disk/pattern handles, reach ring on ice, swapped return zones & holes

## 1. On-map `disk size` and `score pattern` handles (replacing `diskScale` checkbox)

Replaced the editor drawer's binary `Big-disk scales contents (scale | crop)`
checkbox and `CFG.diskScale` flag with continuous relative score-pattern scaling
(`CFG.scoreScale = 1`, `100 %` of the big disk by default) and two on-map handles
in `js/zone-editor.js`:

- **`disk size` handle** (`(diskX + diskR, diskY)`): resizes `cfg.diskR` and
  automatically updates the default angular speed (`game.setOmega(autoOmega(cfg))`)
  so the hold / out-of-friction ring (`holdRadius`) stays proportional at `0.9 R`.
- **`score pattern N%` handle** (`diskR * scoreScale` along the `0.38 rad` ray):
  scales the score map relative to the current big-disk radius (`25 %`–`300 %`,
  clamped inside `[0.25, 3]`). Because `scoreScale` defaults to `1`, resizing the
  big disk scales its score pattern proportionally unless adjusted; when
  `scoreScale !== 1`, a dashed guide circle marks the pattern radius on the
  editor overlay without flipping `customGeometry`.
- **Homothetic evaluation & cache keys** (`js/field.js`, `js/score.js`,
  `js/vote.js`, `js/bots.js`, `js/render.js`, `js/fx-glass.js`): `patternScale(cfg)`
  computes `(cfg.diskR / DISK_REF_R) * (cfg.scoreScale || 1)` against the load-time
  `DISK_REF_R = 0.80` and scales `(ux, uy)` in `fieldLocal` (`f === 1` on the
  shipped board, preserving bit-identical evaluation). Score LUTs (`lutKey`),
  speed-vote hold profiles (`holdProfile`), disk textures (`texScore`), soft glass
  fields (`softScale`), bot `schema.aims`, and the disk spin tick all track
  `diskR` and `scoreScale`.
- **Presets & URL keys** (`js/presets.js`, `js/ui.js`, `index.html`): added
  `scorescale` (`NUM_RANGES.scoreScale = [0.25, 3]`) and removed the obsolete
  `diskScale` key from `PRESETS.notsobigdisk` (which now scales proportionally by
  default at `scoreScale = 1`).

## 2. Hole dashed reach line drawn on ice, never on black

When `holes filled black` (`opts.holeFill`) was enabled, the dashed reach ring
(`hole.r + cfg.puckR`) was stroked on top of the black capture fill so half of
each dash sat over black.

- **`drawReachRing` before any black fill** (`js/render.js`): for `'classic'` and
  `'well'` holes (`'rim'` stays rim-only), every reach ring is stroked before any
  `HOLE_DARK` fill, and shifted outward by `RING_HALF = 0.006` (half of the
  `0.012 m` stroke width) when `holeFill` is on so `100 %` of the dashed stroke
  sits on the ice outside the black capture disk.

## 3. Swap return zone and holes (except right return zone)

Implemented `CFG.swapZones` (`#chkSwap` in the `return pucks` panel fieldset,
mirrored in the board editor drawer, and URL parameter `swap=0|1`):

- **Swapped return zones** (`js/rules.js`, `js/render.js`): the round/wall hole
  capture regions (`holeGap(cfg, hole, x, y) <= cfg.puckR`) become circular return
  zones with teal `Z_FILL`, `Z_HATCH`, dashed `Z_LINE` outlines and `'RETURN'`
  labels, while the right return zone near start (`x >= advanceZone.lx` launch
  strip in `'advance'`, or the `x >= advanceZone.lx` fan slice in `'zones'`)
  remains a return zone. `recyclePucks` runs whenever `mode !== 'none' || cfg.swapZones`.
- **Swapped black hole / void** (`js/rules.js`, `js/physics.js`, `js/bots.js`,
  `js/render.js`): `swapVoidField(cfg, mode, x, y)` turns the old return zone
  wedge/fan (clipped outside `advanceZone.lx - SWAP_HOLE_GAP` and keeping a `3 cm`
  channel around the circular return zones) into the active void (`-1` in `'none'`
  mode). `findEvent` skips `cfg.holes` when swapped, `absorbBlackHoles` swallows
  pucks with `inSwapVoid(...)`, bots push opponent pucks toward the swapped void,
  and `bakeSwapVoid` pre-bakes marching-squares `Path2D` contours (`reachOut`,
  `capture`, `core`, `mid`, `deep`) and interior `'VOID'` labels in
  `buildZonePaths()` with zero per-frame allocations and full `holeStyle`,
  `holeFill` and glass-skin clip support.
