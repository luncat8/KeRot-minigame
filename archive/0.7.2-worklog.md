# 0.7.2 worklog — Multiplayer plan review fixes, hole capture visuals

## Multiplayer plan (0.8-multiplayer-plan.md)

Reviewed the plan against the codebase and folded the gaps in as plan changes (the
plan stays a clean artifact — no implementation started):

- **Full canonical `start` cfg** (§5): the start event now carries the whole setup
  (geometry, ω, μ, mass, disk schema, return rule, zone/hole styles, `diskScale`,
  balls, throw cap, vote rule/mode, bot strategy, warp numbers, seats), and clients
  hash it and abort the match on mismatch. The old three-key subset could let two
  clients diverge in scoring/physics silently.
- **Host-serialized turns** (§1, §5): clients send `throw` to the host only; the
  host validates turn order and broadcasts `{t:'throw', seq, ...}` in order; a turn
  advances only after the host's broadcast. The P2P mesh keeps `seq` + reorder +
  retransmit but never decides turn order itself.
- **Versioned resync** (§1, §5): `{t:'sync', seq, dump}` — the dump is the state
  after throw `seq`; a dump newer than the requested `seq` is refused.
- **Resync-source election** (§1): if the host leaves, the peer with the lowest seat
  index among those that applied the most throws becomes the source.
- **Stall protection** (§1): a per-turn host timer forfeits (skips) a turn that
  never arrives — the only anti-grief rule a casual game needs.
- **Room codes 8+ chars** (§3): P2P matchmaking on a public relay cannot check
  occupancy, so short codes collide.
- **Trystero claim softened** (§2): "no server of ours to register on" — the path
  still rides third-party Nostr relays and public STUN and can fail behind strict
  NAT; relay mode is the fallback.
- **GitHub Pages caveat** (§3): private-repo Pages is restricted; HTTPS is required
  for `wss://`/WebRTC.
- **Votes as inputs** (§1, §5): human speed votes are broadcast events tallied
  identically on every client; remote human seats show a visible "waiting" state.
- **Hosting table** (§4): marked "re-verify the limits at implementation time".

## Hole capture visuals

The hole was visually misleading: a puck is swallowed when its **centre** reaches
`hole.r + puckR`, but the dark void is only `hole.r`, so the puck popped out of
existence the moment its **edge** touched the void rim — it never visibly entered
the hole.

- **The outer dashed ring is the puck-centre locus** (`js/render.js`): drawn at
  `hole.r + cfg.puckR` — exactly the set of puck centres that fall — so the ring
  grows with the puck radius (the geometry was already correct; the comment now
  states what the ring means).
- **"holes filled black" view option** (`js/render.js`, `js/ui.js`, `js/presets.js`,
  `index.html`, `js/zone-editor.js`): a checkbox in the view settings (next to eject
  ring / ghost trajectory) fills every hole's whole capture region — the shape grown
  by the puck radius, i.e. `holeClip` — solid black. A puck then visibly slides onto
  the black and falls when its centre reaches the dashed ring, matching the rule.
  Purely visual: physics, capture timing and scoring are untouched. Works for the
  round voids and the triangle void (whose capture region is the grown triangle).
  Wired like the other view toggles: `opts.holeFill`, URL key `holefill=1`, echoed
  into the live link and preset echoes, carried in the editor's copied setup, and
  left out of the link when off (the shipped default). The minigame bundle passes
  no `holeFill`, so it renders exactly as before.
