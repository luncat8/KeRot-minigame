# 0.1.8 worklog — speed-vote strategy review

Reference: `archive/0.1.8-plan.md` and the existing 0.1.7 speed-vote implementation.

## Review findings

- The old wording that the other seats *want* every next player to have less room was
too absolute. Under `turn`, voters can have a targeted denial incentive, but each bot
also prices its own locked scoring pucks. The `round` default remains the safer,
less-targeted rule.
- The core rider calculation already charged an own locked puck at its red score rate
when the candidate ramp would shed it. A hard ban on speed-ups would have been the
wrong fix: a speed-up can be useful when an own rider survives and a valuable enemy
rider does not. Added regression cases for both situations, including a black-hole bot
with its own high-scoring, exposed rider.
- **Vote timing mismatch:** bot candidates were priced as if a new ramp began at the
old setpoint. If a previous ramp is still in progress when a vote closes, the actual
new ramp begins from the live speed at closure. The bot now forecasts that speed from
the existing ramp and `voteT`, evaluates rider survival from that start, and excludes
riders that the old ramp would already shed before the vote closes.
- **Exact bot search omitted the range endpoints** when the current speed was not
aligned to the 0.02 rad/s grid. The candidate list now includes 0, `omegaMax`, and the
current setpoint in sorted order; the plateau midpoint is calculated from actual speed
values.
- **The panel did not match its plan:** the omega slider/readout showed `CFG.omega`
(the target), not the live motor speed during a vote ramp. `Game.omegaNow` now exposes
the live speed, and the slider follows it while the readout labels a ramp target and a
voted starting speed separately.
- A direct speed set now updates the live motor immediately. This could bypass the
physics' normal still-disk wake check, so the direct 0 → positive path explicitly
wakes pucks the disk can no longer leave asleep; a regression gate covers it.

## Next step

and after a tally. Use it to tune `VOTE_PARK` and profile denial only if a bot is shown
