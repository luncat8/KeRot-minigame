# 0.1.0-plan — Rotating disk curling: physics core, playable loop, scoring

Reference requirement: `0.1.0-draft.md`. This plan is the implementation artifact for a from-scratch
rebuild; it assumes nothing about earlier code.

## 0. Inherited state (review)

Initial commit only: `index.html` with a bare `<canvas id="c">` inside `#app`, no scripts, no styles,
no title; `AGENTS.md` conventions; empty `findings-pitfalls-skills.md`. Nothing to fix or carry over —
the whole game is new. `index.html` is kept as the single page (classic scripts, `file://` friendly).

## 1. Answers to the draft's three questions

**1. Own integrator or Box2D/planck.js? → Own integrator.**
The scene is 4 walls + N circles + one rotating plane. Everything the draft asks for is *cheap* to do
exactly, and is *hard* to do in an engine:

| requirement | own solver | Box2D/planck |
|---|---|---|
| no tunneling | analytic time-of-impact, exact by construction | swept TOI only for static bodies; dynamic–dynamic is discrete + iterative → fast puck–puck can tunnel |
| friction against *two* surfaces under a straddling puck (floor + rotating disk), weighted by contact area | one expression (see §4.3) | needs two fixtures/contacts plus its own friction-mixing law; the weighting is not expressible |
| exact static criterion "co-rotates while ω²d ≤ μ_s g" (the 90 % rule) | direct, testable | emerges from a velocity-bias/impulse solver, tune-by-feel only |
| determinism + headless node runs for experiments | pure typed-array functions | heavier, but possible |
| payload / hot-path allocations | ~500 lines, zero deps | vendored ~400–700 KB, own world/alloc behaviour |

An engine wins only if the game later needs polygonal/irregular geometry, stacking, or a broadphase
for hundreds of bodies. Not here.

**2. Direction of the rotational impulse (friction against disk vs floor).**
Work in the lab frame only; never add fictitious centrifugal/Coriolis terms. Friction on the disk
opposes the puck's velocity **relative to the local disk surface velocity**, i.e.
`v_rel = v − v_surf`, `v_surf = ω·(−dy, +dx)` with `(dx,dy) = p − disk center` (world is y-down, so +ω
is clockwise on screen). Friction on the floor opposes `v`. The classic mistake is to use `v` against
the disk: then a puck lying on the spinning disk loses energy instead of being dragged and flung.
Everything the draft asks for (spin-up, outward spiral, ejection) falls out of `v_rel` friction
without any centrifugal term: a puck at rest in the lab frame on the disk feels friction along `+v_surf`
which accelerates it tangentially, and straight-line motion along a tangent increases its radius.

**3. "Since the pucks are round, simply calculate the collision time."** Yes — it is a single quadratic
(§4.5), so the collision is resolved at the exact instant with zero overshoot and no speculative
contacts.

**Mass note (correction of the draft's premise):** the ejection criterion `m ω²d ≤ μ_s m g` *cancels
mass*, and so does the throw (a stroke sets a velocity, not a force). Mass therefore affects only
puck–puck momentum exchange. The 90 % rule reduces to choosing `ω` (given `μ_s`, `R`) — implemented as
`ω = √(μ_s g / (0.9 R))` plus a UI "auto" button and a live readout (§4.4). Mass stays a per-puck
property (default 4 kg, granite puck of r=0.10 m × 0.05 m).

## 2. World, units, conventions

- SI everywhere: meters, seconds, radians, kilograms. Gravity `g = 9.81`.
- World axes: **x right, y down** (screen-aligned, no flip in the renderer). Consequence: positive
  angular velocity rotates **clockwise** on screen; the perpendicular of `d = (dx,dy)` is `(−dy, dx)`.
- 2D top view; pucks have no moment of inertia in the dynamics (justified: a flat surface contact
  exerts no net force on the puck's centre through spin; only a spin-down torque, which is ignored —
  optional visual spin later, §12).
- One simulation plane: floor and disk are coplanar; the disk rim is **not** a wall, it is a friction
  boundary a puck slides over freely.
- No randomness anywhere in the sim. Same inputs → same state (needed for tests and for the ghost
  preview of §12).

## 3. Board geometry (`js/cfg.js`)

```
BOARD  W 3.60 × H 2.20 m            walls: rect, restitution e_wall = 0.35, tangential keep 0.85
DISK   R 0.80 m, centre (1.10, 1.10) → moat 0.30 m on left/top/bottom (a 0.20 m puck passes it)
       ω default = 0.7831 rad/s = √(μ_s g / (0.9 R))   → period 8.0 s, rim speed 0.63 m/s
PUCK   r 0.10 m, m 4.0 kg (20 cm granite puck; real stone: r 0.145, m 19.1)
LAUNCH zone x ∈ [3.05, 3.45], y ∈ [0.95, 1.25]; spawn (3.25, 1.10); throw distance to disk centre 2.15 m
```
Disk occupies the left of the board (draft requirement); the open floor to the right is the delivery
area. Pucks always remain in the bounded board (walls), so "pucks remain on the board, points tallied
at the end" holds.

## 4. Physics

### 4.1 State and step

```
World = {
  cfg,                                    // live copy of the tuning table (§4.4)
  t, theta,                               // sim time, disk angle
  n,                                      // pucks in play
  x,y,vx,vy,r,m : Float64Array(MAX=32),
  st : Uint8Array(MAX)                    // 0 AIR/floor, 1 SLIDING on disk, 2 LOCKED, 3 SLEEPING
  phase, score, events[]                  // timestamped input events (§5)
}
stepWorld(w, h)  // h = fixed 1/480 s
```

### 4.2 Contact classification (per puck, per slice)

Area fraction of the puck that lies inside the disk (`d` = distance between centres), exact circle
intersection area; cheap because it is only evaluated when `|d − R| < r`, otherwise `a ∈ {0,1}`:

```
a = 0                                  if d ≥ R + r
a = 1                                  if d ≤ |R − r|
A = r²·acos(c1) + R²·acos(c2) − ½√((−d+r+R)(d+r−R)(d−r+R)(d+r+R))
a = A / (π r²)                         c1 = (d²+r²−R²)/(2 d r),  c2 = (d²+R²−r²)/(2 d R), args clamped
```
`a` is continuous in `d`, so entering/leaving the disk does not produce a force jump beyond the
physical one.

### 4.3 Friction: sliding, static, co-rotation lock

Per slice, using `a`, `v`, and the disk surface velocity `v_surf` at the puck centre:

```
SLIDING:   a_disk  = −μ_k g · â(v − v_surf) · a            (0 when |v − v_surf| < εv)
           a_floor = −μ_k g · â(v)        · (1 − a)         (0 when |v| < εv)
           v += (a_disk + a_floor)·h  ;  |a_disk + a_floor| ≤ μ_k g  (triangle ineq., no clamp needed)
LOCK test  (only when a ≥ 1 − 1e−3, i.e. puck fully on the disk):
           if |v − v_surf| ≤ ε_lock and ω²·d ≤ μ_s·g   → st = LOCKED, v = v_surf
           (hysteresis: unlock when a < 0.98, or |v − v_surf| > 2·ε_lock, or ω²·d > μ_s·g)
FLOOR rest (a ≤ 1e−3):  if |v| ≤ ε_sleep → v = 0, st = SLEEPING
```
Locked pucks are advanced by *exact rotation* about the disk centre, not by a tangent step: a tangent
step grows the radius by ~(v·h)²/2d every step and would slowly eject a puck that should be held.
Sleep requires |v − v_surf| ≤ ε_sleep only where the puck actually touches the disk (a > 1e−3);
v_surf is defined over the whole plane, and gating sleep on it off-disk means floor pucks never sleep.
Consequences, all matching the draft: a puck delivered onto the disk gets spun up by friction, spirals
outward (centrifugal behaviour without any centrifugal term), and either settles into co-rotation inside
the holding radius or is carried past the rim and leaves the disk. The lock is re-evaluated every step,
so a collision that perturbs a locked puck unlocks it automatically (no collision hooks needed).

Zero-crossing pitfalls handled explicitly: kinetic friction is applied as a velocity decrement, so a
puck's speed reaches exactly 0 in finite time; without the `ε_sleep` snap it would jitter around zero
and would never fall asleep. Same for `εv` on the relative velocity.

### 4.4 Tuning table and the 90 % invariant

| symbol | meaning | default | slider range | note |
|---|---|---|---|---|
| `μ_k` | kinetic friction | 0.030 | 0.005 – 0.30 | ice/ice; a real curling stone (μ≈0.02–0.05) glides 9–23 m, board is 3.6 m |
| `μ_s` | static friction | 0.045 | μ_k – 0.50 | must be ≥ μ_k; the slider's min follows μ_k |
| `ω` | disk angular speed | 0.7831 | 0 – 2.0 rad/s | derived, see below |
| `v_max` | max throw speed | 1.40 m/s | – | stopping distance `v²/(2μ_k g)` = 3.3 m ≈ one board length |
| `e_wall` | wall restitution | 0.35 | – | plus 15 % tangential loss ("cushion") |
| `e_puck` | puck restitution | 0.65 | – | granite on granite with a running band |
| `h` | sim step | 1/480 s | – | see §5 |
| `ε_lock` | lock threshold on \|v−v_surf\| | 0.010 m/s | – | |
| `ε_sleep` | rest threshold on \|v\| | 0.004 m/s | – | |
| `SLOP` | contact skin | 1e−6 m | – | separation after an impulse; keeps the next TOI positive |
| `MAX_SUBSTEPS` | events per step | 8 | – | fallback path: finish the slice without further events |

**Holding radius / 90 % invariant.** A co-rotating puck needs centripetal `m ω² d`, supplied at most by
`μ_s m g`, hence it is held while `d ≤ d_hold = μ_s g / ω²`. Defaults are chosen so
`d_hold = 0.9 R` exactly:

```
ω_default = √(μ_s g / (0.9 R)) = √(0.045·9.81 / (0.9·0.80)) = 0.7831 rad/s
```
UI: dashed eject ring at `d_hold`, hatched outer annulus `[d_hold, R]`, live readout `d_hold/R` in %,
"auto-ω (90 %)" button that re-solves `ω` whenever `μ_s` changes, and a warning when `d_hold > R`
(`ω` too low: nothing is ever ejected) or `< 0.2 R` ("meat grinder"). A `experiments/eject-radius.js`
table asserts the identity `d_hold(ω, μ_s) = μ_s g/ω²` and the 0.90 ± 0.001 default.

### 4.5 Collisions (exact time of impact)

Per slice we hold the friction classification fixed, find the earliest event, advance *all* pucks to it,
resolve, and repeat for the remaining slice (`t += τ`, ≤ `MAX_SUBSTEPS`).

- Wall (4 axis planes): `τ = (r − x)/vx` for `vx<0`, etc.; take the smallest positive `τ ∈ (0, h−t]`.
  Impulse: `v_n ← −e_wall·v_n`, `v_t ← 0.85·v_t`.
- Puck–puck, radii sum `σ`, `d = p_j − p_i`, `v = v_j − v_i`:
  `(v·v)τ² + 2(d·v)τ + (d·d − σ²) = 0` → `τ = (−(d·v) − √disc)/(v·v)` if `disc ≥ 0` and `d·v < 0`;
  impulse `j = −(1+e_puck)(v_rel·n)/(1/m_i + 1/m_j)` along `n = normalize(d + v·τ)`, then separate the
  residual overlap positionally by inverse mass + `SLOP`. Already-overlapping pairs (spawn) resolve at
  `τ = 0` with separation and an impulse only if approaching (never inject energy).
- Simultaneous contacts (corner, three-body) are serialized by the substep loop; `SLOP` guarantees
  strictly positive next-TOI, so the loop terminates. If `MAX_SUBSTEPS` is exhausted, the remaining
  slice is advanced without events and positions are clamped into the board (2 lines, the only guard).
- No friction or spin in collision impulses (stone-on-stone), no speculative contacts.

### 4.6 Sleep, resolve, spawn

A puck is `asleep` when LOCKED or SLEEPING. A throw resolves when every puck is asleep (then the next
stroke is unlocked) or after `MAX_RESOLVE = 8 s` (then a still-moving puck keeps moving in the
background — like a stone still travelling while the next one is delivered). Spawning the next puck
inside the launch zone where a stopped puck already sits is resolved by pushing the older pucks out
along the centre line (position only, zero velocity).

### 4.7 End of game

After the last puck resolves: **spin-down** — `ω` ramps linearly to 0 over 3 s (θ integrated
trapezoidally); LOCKED pucks stay locked while `|dω/dt|·d ≤ μ_s g` (0.19 ≪ 0.44 m/s², holds), all
pucks become SLEEPING once the disk stops, then the board is scored. This makes the final phase
deterministic and gives a visible settling beat. `CFG.endMode = 'settle' | 'freeze'` keeps the
alternative (score immediately at the resolve instant, which makes the score depend on the live disk
phase).

## 5. Frame-rate independence contract

- Fixed step `h = 1/480 s`, driven by a time accumulator: `acc += dt; while (acc ≥ h && n < 96)
  { stepWorld(w, h); acc −= h; n++ }`. 30 Hz display → 16 steps/frame, 165 Hz → 3; identical physics.
- `dt` is clamped to 0.25 s and the tab is paused on `visibilitychange` (no time-skip on return).
- A leftover backlog beyond the cap is dropped, documented, never simulated later as one huge step.
- Inputs are timestamped (`event.timeStamp`) and queued with the **sim time** they belong to, so a
  throw is applied at the step whose interval contains it — the frame cadence cannot shift the throw by
  more than one `h` (2 ms). Human reaction time is the only remaining frame-rate dependence, which is
  inherent to any real-time game and not a property of the physics.
- Nothing in render/UI feeds back into the sim: the field is a pure function, the disk texture is baked
  from it, the HUD only reads.

## 6. Field (the coloured zones) and scoring

Value at any world point, sources attached to the disk (they rotate with it, so the same expression
scores inside and outside the disk):

```
u   = R(−θ)·(p − C)                       // disk-local coordinates
V(p)= clamp( BIAS + Σ w_i·exp(−|u − s_i|² / (2 σ_i²)),  −1, +1 )
```
`Σ`-of-blobs (not normalised): a source paints its own blob, `BIAS` cools the whole plane, so the red
core is reachable only on the disk and the floor is uniformly cool. `V = −1` blue → `0` light →
`+1` red (diverging palette, monotone in `V`).

Preset (`R = 0.80 m`; a table, cheap to re-author, one row per point):

| local pos (m) | weight | σ (m) | role |
|---|---|---|---|
| (0.00, 0.00) | +1.25 | 0.256 (0.32 R) | red core "the button", always on the disk, `V ≈ +1` |
| (+0.36, 0.00) | +0.85 | 0.240 (0.30 R) | red lobe — **rotates**, so timing matters |
| (−0.36, +0.36) | −0.85 | 0.240 | blue lobe |
| (−0.36, −0.36) | −0.85 | 0.240 | blue lobe |
| — | BIAS = −0.30 | — | the floor and the rim are cool/blue |

Verified numerically for the preset above (200² grid over the disk): 14 % of the disk area has `V > 0.5`,
4 % is saturated at `+1`, `V(rim) ≈ −0.13`, the far floor is uniformly `BIAS = −0.30`, and the `V = 0`
crossing along the local +x axis lands at `0.719 m` — i.e. **the warm (point-earning) region ends
almost exactly at the eject ring `d_hold = 0.72 m`**. That coincidence is a property of the default
tuning, not an invariant, but it makes the default game coherent: a puck the disk can no longer hold
is also a puck outside the scoring red, so the centrifugal rule and the point field pull in the same
direction. Keep it in mind when re-authoring the source table.

**Score = Σ_pucks V(final puck centre)** after §4.7 (max +1 per puck `× 8 = +8`). Pucks in a blue lobe
or flung off onto the floor score negative, which is exactly the drama the draft's centrifugal rule
creates. HUD shows a per-puck breakdown (index, position, `V`, contribution) and the total; the live
total is displayed while playing, the recorded one at the settle instant. `SCORE_MODE` flag left for the
curling-style alternative (count the pucks closer to the red core than the opponent's — needs teams,
§12).

## 7. Rendering (`js/render.js`)

Canvas 2D, one element, letterboxed: `scale = min(cssW/BOARD.W, cssH/BOARD.H)`, transform set once per
frame (`setTransform(s·dpr, 0, 0, s·dpr, ox, oy)`), world y-down so no flips anywhere. Layers, back to
front:

1. Floor: baked ice tile (a 64² noise pattern created once) + faint field copy: the baked field
   texture drawn rotated by θ at `FLOOR_ALPHA = 0.35`, clipped to the board.
2. Walls: rounded-rect stroke (path rebuilt on resize only).
3. Disk: opaque base circle, then the crisp field texture rotated by θ clipped to the circle; rim
   stroke; a radial tick that spins with the disk (readability of the rotation); dashed eject ring at
   `d_hold`; source markers — **debug flag only**: the default weights push `V` to exactly `+1` over the
   core, so markers there would leak the hidden layout without telling the player anything true.
4. Aim: stroke arrow from the spawn point, dashed straight first-leg line, live speed and stopping
   distance labels (strings precomputed, §9).
5. Pucks: cached radial gradient (created in *local* coordinates at setup and drawn under a
   `translate`), body, index ring colour, `fillText` of a precomputed label, sleeping pucks dimmed, the
   pending puck drawn as a ghost at the spawn.
6. Score chips / state text drawn as DOM, not canvas (§8).

Field textures are baked into offscreen canvases **twice**: `texDisk` (disk-local, 2·R box, resolution
`clamp(2·onScreenScale, 96, 512) px/m`) and `texFloor` (board-local, low-res), re-baked only on
resize/DPR change or if the source table changes. Because the field is smooth by construction, low-res
+ bilinear upscaling is visually lossless, so per-frame cost is 2 clipped `drawImage` calls.

## 8. Input, UI, game flow

`index.html`: canvas + a side panel of native controls (no framework): range sliders for `ω`, `μ_k`,
`μ_s`; buttons `Throw ␣`, `Clear`, `auto-ω (90 %)`, `Reset board`, `Pause`; checkboxes `eject ring`,
`preview line`; readouts `d_hold/R`, stopping distance, sim time, steps/frame, puck k/n, live score.

State machine (`js/game.js`): `STROKE` (aiming, editable) → `RESOLVE` (simulating until asleep/cap) →
… → `SETTLE` (spin-down, §4.7) → `SCORED` (breakdown + reset). A stroke is a world-space vector:

- Pointer: `pointerdown/move/up` with capture; `stroke = pointerWorld − spawn`, `v = clamp(|stroke| /
  DRAG_FULL, 0, 1)·v_max` with `DRAG_FULL = 0.90 m`, direction = drag direction (a flick **forward**);
  `touch-action: none`; works with mouse and touch (touch = same code path).
- Space (or the button) commits the throw; **before** committing, any new drag or `Esc` redefines/clears
  the stroke (draft requirement: "make a new stroke before throwing if they don't like the previous
  one"). Arrow keys nudge angle (±1°, ±0.2° with Shift) and power (±2 %); `R` resets the board.
- The HUD is updated only when a value changes, throttled to ~5 Hz for the numeric readouts.

## 9. Files, module API, hot-path rules

```
index.html      canvas + panel + <style>; classic <script> tags in order (no modules, no build):
                cfg.js → field.js → physics.js → render.js → ui.js → game.js → main.js
js/cfg.js       DEFAULTS/CFG table, board/disk/puck constants, field source table   [node-safe]
js/field.js     valueAt(p), bakeField(canvas, box, ppm)                             [node-safe]
js/physics.js   createWorld, resetWorld, spawnPuck, throwPuck, stepWorld,
                fieldValueOf, totalScore, isSettled                                [node-safe]
js/render.js    bakeTextures, drawWorld(w, aim)
js/ui.js        slider/button wiring, readouts, CFG mutation
js/game.js      states, input events → timestamped queue, spawn/aim/throw, scoring
js/main.js      boot, resize, rAF loop + accumulator
experiments/    node scripts (never loaded by the page)
```
Node duality: `if (typeof module !== 'undefined') module.exports = {…}` at the end of every node-safe
file; browser files must not touch `document`/`window` at load time. Top-level `const` in classic
scripts gives global lexical bindings visible to later scripts.

Hot path (per frame / per step) — allocate once at setup, mutate in place:

- puck state in typed arrays, fixed `MAX_PUCKS = 32`, no per-step objects, no closures, no `.map/.filter`;
- scratch scalars for TOI/impulse maths (module-level `let`s), no vectors allocated in the loop;
- gradients created once in local coordinates (usable across transforms, drawn under `translate`);
- labels/HUD strings precomputed, `fillText` reuses them; DOM text updated on change only;
- textures/paths rebuilt on resize only; the renderer never mutates the world.

## 11. Manual validation checklist (live preview over `python3 -m http.server`, bound to 0.0.0.0)

1. Throw along the disk's centre line: the puck is visibly spun up and curves; a slow throw comes to
   rest in the holding zone and then travels in a perfect circle with the disk.
2. A puck entering outside the eject ring spirals outward, leaves the rim with rim-tangential velocity,
   and stops on the floor; the outer 10 % never holds anything.
3. `μ_s → 0`: nothing is ever held (everything slides off). `ω → 0`: nothing is ejected. `μ_k → 0`:
   the puck glides and bounces almost forever (degenerate but valid).
4. A puck at rest on the floor stays at rest; a resting puck hit by another wakes and moves.
5. Rim crossing looks continuous: no jump in speed when the puck straddles the rim (see the `a` ramp).
6. Slider changes take effect immediately and the readouts (`d_hold/R`, stopping distance) agree with
   the experiment tables.
7. Same stroke repeated at 30 Hz and 144 Hz dev caps gives the same final resting spot (±1 px).
8. Score: pucks on the red core are +, a puck flung to the far right floor is ≈ −0.3, the settle phase
   runs, and the per-puck breakdown sums to the total. Cross-check the field against the numbers in §6
   (14 % of the disk above +0.5, 4 % saturated, `V = 0` at ≈ 0.72 m along +x).

## 13. Open decisions (defaults chosen, easy to flip)

1. Single player, 8 pucks (not teams/alternating colours).
2. `SCORE_MODE = sum` (Σ V) as above, not curling count-the-closest.
3. `endMode = 'settle'` (spin-down then score), not freeze-at-resolve.
4. Ice friction defaults (μ_k 0.03, μ_s 0.045) with ω derived for the 90 % rule, rather than a faster,
   "arcade" disk; both are on sliders anyway.
