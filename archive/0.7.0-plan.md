# 0.7.0 plan — Lazy board editor and reproducible geometry

## Scope

A standalone-page **Edit board** button lazy-loads `js/zone-editor.js`, its drawer and
transparent handle canvas. No editor code, overlay, listeners or animation loop on an
ordinary visit. Classic scripts, file:// friendly, no dependencies. Snowfall stays editor-free.

## Lifecycle

Editing pauses gameplay, cancels bot planning and pending input, and starts a clean preview.
Pointer/keyboard throwing and restarting are blocked while editing; Escape or the entry
button closes it. Geometry updates reset the paused preview so puck radii, mass/inertia,
launch placement and stock all agree; old scores/overlaps never survive a resize. Closing
starts a fresh game, preserving the pre-editor pause preference. Closing retains edits;
normal game Reset also retains settings, like existing sliders. Revert edits restores the
setup captured at entry. Tear down overlay, drawer, events and resize observer on close.

## Shared geometry contract

`cfg.js` owns snapshot, validation, application and derived-zone rebuild helpers. A geometry
setup includes board width/height, disk centre/radius, both hole centres/radii, puck radius,
launch bounds/position, zone reach and clear-ice gap. Validate finite numbers, board bounds,
puck size, disk/hole separation and a usable launch lane; boundary holes may have
centres on a wall. Clone nested state rather than aliasing defaults. Clamp pointer proposals
and stop at collision boundaries; invalid imported geometry is ignored atomically.

Wedge/fan reach scales the corner rays about the disk apex; field styles retain their
existing derived outlines. Cut-zone gap becomes `cfg.zoneCutGap` (default 6 cm); soft styles
keep their existing blend. No raw outline vertices. Disk markings remain in physical metres,
as in the existing field/bot schema; radius changes clip/reveal that map rather than rescale it.
Rebuild renderer geometry, radius-dependent disk texture and optional glass caches after edits.
Keep scoring's per-schema/radius LUT cache bounded under repeated drags.

Custom boards retain explicit dimensions across viewport changes: responsive canvas resizing
must not reposition their disk/holes or overwrite launch geometry. Unedited boards keep the
existing responsive fit. The copied board therefore reopens consistently on another screen.

## Controls

- Drag disk centre/rim and each hole centre/rim.
- Drag return/fan reach, cut-zone gap, puck size and launch lane edges/centre.
- Label handles; also expose every geometry value as a labelled numeric input for precise
  or keyboard-only editing. Numeric feedback and constraints in metres.
- Drawer selectors: disk schema, return rule, zone style, hole style; numeric omega,
  balls per player and max throws. Existing seat types (including `timing`) remain intact.
- Copy preset: URL, canonical setup JSON and readable summary. A selectable text area is
  always available; use clipboard API, then file:// copy fallback, report failure honestly.

## Sharing

Extend `parseQuery`/`applyCfg` with validated `geometry` JSON and `maxThrows`; geometry is a
first-class setup key, not an unparseable note appended to an otherwise incomplete URL.
Use canonical setup keys (`muK`, `muS`, `puckM`, `voteMode`, not their URL aliases) in JSON.
Include rules, physics, roster and bot settings in exported setups. Normal UI URL updates
must retain custom geometry. Default preset clears custom geometry and restores normal fit.

## Validation

Node tests: geometry constraints/malformed input, no mutation on rejected imports, default
independence, derived zone geometry, custom viewport stability, geometry URL/setup round-trip,
editor lifecycle and cleanup, drag/cancel/keyboard/copy fallback and lazy-load failure/retry.
Run timing/speed-vote, zone shapes, client/fx smoke, deterministic physics, minigame smoke and
bundle drift gates. Browser check desktop/narrow layout and pointer mapping after resize.
