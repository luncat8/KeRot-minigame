## Review of the previous round

Branch is fresh off `5263385816d19982a4c8b7f336423316a687db92`. The brief: add a bot
strategy + character that, once its pucks out-earn the opponents from the scoring area,
favours *slower, longer turns* to give its positioned pucks more time to score.

First cut was a `staller` that tried to **extend** the turn (a `stall` term rewarding
`lead · duration` in `evaluateStroke`, plus a lead-gated disk-slow vote). Validation showed
it works mechanically, but the user-corrected the premise: **the scoring window is
hard-capped at `handoffT`, so a longer turn does not pay more** — every candidate throw
already saturates at 4.00 s under the default friction, and the rule "covers" the
extend-turn exploit. So the duration term was a no-op in practice. The real lever is
*how the fixed window is spent*: get pucks dwelling in red (and double-passing the zone)
rather than only building the best end-state.

## Steps (final: the `timing` bot)

1. `js/bots.js`
   - Removed the dead `stall · lead · duration` term from `evaluateStroke` and the
     `stall` weight from every profile. `evaluateStroke` is again profile-agnostic
     except for the existing preferences.
   - Added the `timing` profile: **high `score` (1.70), low `opportunity` (0.55)** —
     it weights the *within-turn* red-time (`ownIntegral`) far above the far-future
     lock (`ownOpportunity = stableΔ · future`), so it throws to get pucks sitting in
     red and double-passing the zone instead of merely setting up the best resting state.
     High `risk` (1.35) protects the lead it builds; `patience: 1.2` for the vote lever.
   - Exported `evaluateStroke` (was module-scoped) so the headless check can call it.
2. `js/vote.js` — `chooseVote` keeps the lead-gated disk-slowdown but keys it on a new
   `patience` weight (renamed from `stall`). This is a genuine *use-the-time* lever, not
   an extension: a slower disk rotates less, so a parked puck does not rotate off its red
   lobe during the window it is given. Gated on `p.patience` (only `timing`) and only
   when a speed vote is due — "if the rules allow".
3. `js/players.js` — registered `timing` in `SEAT_TYPES` / `SEAT_LABELS` (`bot — timing`).
4. `experiments/` — `bot-strategies.js` league now lists `timing`; replaced
   `staller-check.js` with `timing-check.js` validating the new behaviour.

## Decisions

- **Rename `staller` → `timing`.** The action is timing, not stalling: every turn already
  lasts exactly the capped window, so the skill is filling that window with red, not
  lengthening it.
- **No special term beyond the profile weights.** `evaluateStroke` already integrates
  score over the window (`ownIntegral` = total red-rate × time, including transits and
  dwell), so a double-pass or an early stop-in-red already scores more than a puck that
  arrives at the close. The timing bot simply *weights that signal harder* than the
  far-future lock — matching the codebase's "every profile scores the same candidates,
  only preferences differ" design.
- **The disk-slow vote stays**, reframed as `patience`: it is the one real "use the time"
  knob left, and it only fires when the timing bot is already ahead (protect the lead).

## Validation

- `experiments/timing-check.js`: a puck dwelling in red is preferred by **+110.8** for
  timing vs **+17.4** for `random` (≈6× the weight on within-turn red-time — the
  character's signature). When ahead, timing votes **−0.48 rad/s** (slow the disk) vs
  **+0.50** when behind; exact-mode asks **0.07** against the current **0.78**. All OK.
- `experiments/bot-strategies.js` (5 seeded games, classic): timing is the **top scorer
  (306 ± 138)** and ties the win lead (**40 %**), with the fewest pucks lost to holes
  (1.6). `speed-vote.js` still passes — the `patience` gate is a no-op for the other
  profiles, so their behaviour is unchanged.
