# 0.1.3-plan — stroke range, puck spin, one return fan, ghost refresh

Reference requirement: `0.1.3-draft.md`. Standalone implementation artifact: it
states the design decisions and their measurements, not the history of the work
(that is `archive/0.1.3-worklog.md`). Multiplayer stays planning-only in
`0.1.2-plan.md`.

## 0. Inherited state (review of 0.1.1)

`archive/0.1.1-plan.md` is implemented and its gates pass. Findings of this round:

1. `game.js` `nudge()` ignored `shiftKey` for speed while using it for the angle,
   and the drag had a single fixed gain — the draft asks for a precise mode.
2. `render.js` drew pucks as plain circles + an index number: no way to see that a
   puck is spinning (the physics had no spin at all — the 0.1.0-draft line
   "it should receive rotational impulse from friction against both the ordinary
   floor and the big_disk" was only half-implemented: rotation was applied to pucks
   *held* by the disk, never to a puck's own material rotation).
3. Disk friction was sampled at the puck **centre**, so a puck straddling the rim was
   dragged by the surface velocity under its centre instead of under the patch that
   actually touches the disk (the "partially intersected" case of the draft).
4. The ghost preview was re-simulated only when the *aim* changed: moving a physics
   slider left a stale ghost on screen.
5. `experiments/energy.js` printed a FAIL for the stopping-distance case without
   setting the `fail` flag (silent). Fixed here.
6. `rules.js` `mode === 'behind'` + the gutter zones are replaced by one shape (§3);
   keeping both would leave a dead branch (repo rule: no leftovers).
7. `physics.js` had a **zombie state**: a puck that comes to rest jammed on the rim
   (a ≈ 0.4, v = 0) stayed `SLIDE` forever, because the floor patch cancels whatever
   the disk patch adds each step while the sleep gate demanded the surface-matched
   relative velocity `rv`. Every later resolve then ran into the `maxResolve` cap and
   the round crawled. The sleep gate now also accepts the jam (§2.4); measured
   before/after in `archive/0.1.3-worklog.md`.

## 1. Tuning: stroke speed 0…3 m/s, shift = precision

- `CFG.vMin = 0.0`, `CFG.vMax = 3.0` (was 0.8…4.0). `dragFull` stays 0.90 m, so the
  whole range is one thumb-length of drag and any speed down to 0 is reachable.
- **Precision mode.** While `shift` is held, speed changes are scaled by
  `CFG.preciseGain = 0.25`: the mapping is rebased on every shift transition
  (`anchorLen`, `anchorSp` = the current length and speed), so

  ```
  sp = clamp(anchorSp + (len − anchorLen) · (vMax−vMin)/dragFull · (shift ? 0.25 : 1))
  ```

  is continuous at the press *and* the release (no jump), keeps the plain mapping
  exactly when shift is never pressed (anchor 0,0), and gives ~4× finer resolution
  while held. Arrow-key power nudges use the same switch: ±2 % + 0.01 m/s, or
  ±0.5 % + 0.002 m/s with shift (the angle nudges keep their 1°/0.2° steps).
- With `vMin = 0` a zero-length drag no longer arms a throw (`hasStroke` stays false
  below 1e-6 m), but a deliberately slow release is legal: it simply parks the puck
  in the launch box, which the return fan then hands back to the pool.

## 2. Puck spin (material rotation)

New per-puck state: `th` (orientation) and `om` (angular velocity, rad/s) with
`I = ½ m r²`. Everything below is deterministic, allocation-free and node-safe;
`predict.js` clones `th`/`om` so the ghost and the bots see the same physics.

### 2.1 Friction acts at the contact patch, not at the centre

The disk's surface velocity is linear in position (`v_surf(p) = ω ẑ × (p − c_disk)`),
so its **mean over the contact patch equals its value at the patch centroid**. The
overlap of two circles is a lens; its centroid is the area-weighted combination of
the two circular caps beyond the common chord:

```
a1 = (d² + r² − R²)/(2d)            chord offset from the puck centre, toward the disk
A1 = segArea(r, a1),  A2 = segArea(R, d − a1)        segArea(R,a) = R²·acos(a/R) − a√(R²−a²)
c  = (A1·(puck − h1·û) + A2·(disk + h2·û)) / (A1 + A2),  h = (2/3)(R²−a²)^{3/2}/A
```

`a = (A1+A2)/(πr²)` (the old `diskAreaFrac`, same value). The floor patch is the
complement, whose centroid is `x_cm − a/(1−a)·(c − x_cm)`. Each surface then pulls
the puck's **material** velocity at its own patch centroid toward its own surface
velocity by at most `μk·g·f·h` (`f` = that surface's area fraction) — for a
non-spinning puck this is bit-identical to the old model, because for `f = 1`
(fully on the disk) and `f = 0` (fully on the floor) the centroid *is* the centre.

### 2.2 The spin equation (Coulomb, saturated)

For a round patch the relative material velocity of a spinning puck is a pure
rotation field about the centre, so friction is saturated everywhere except the
centre point: the disk patch drags `om` toward `ω_disk` at `(4/3)·μk·g/r` per unit
covered area, the floor patch brakes it toward 0 at the same rate.

```
rate = CFG.spinDrag · μk·g/r,  spinDrag = 4/3
om += clamp(ω_disk − om, ±rate·a·h)        // only where a > 0
om += clamp(−om,         ±rate·(1−a)·h)    // only where a < 1
```

Clamping each step by the remaining gap is the same "reaches the target exactly"
trick the linear model uses for `dec`. A puck riding the disk therefore spins up to
`ω_d` in ~1 s at defaults (4 rad/s ÷ 3.9 rad/s²) and keeps that spin when flung off,
decaying on the ice over the same ~1 s — which is what makes the 6 sectors visible.
A puck sliding on the floor with no disk contact keeps zero spin (correct: nothing
torques it), and a fully covered puck gains *no* linear curl from its spin, so the
tuned capture/eject behaviour (90 % rule, lock band, death map) is untouched.

The patch-centroid friction force would also produce a moment about the centre; it is
deliberately **not** added — for a round patch that term is second order, while the
saturated spinning friction above is the dominant one. Adding both would double-count
the same physics.

### 2.3 Angular impulses at contacts

- **Puck–puck**: the normal impulse stays central (no torque, disc geometry). The
  contact also rubs: tangential relative velocity is killed up to the friction cone,
  `j_t = clamp(−v_t/K, ±μ_edge·j_n)` with `K = 1/m_i + 1/m_j + r_i²/I_i + r_j²/I_j`
  (`= 3/m_i + 3/m_j` for discs), giving `Δv = ±j_t·t̂/m` and `Δω = −j_t·r/I`. Both
  pucks' spins change by the *same* sign, which is exactly the rolling condition
  `ω_i = −ω_j` for touching discs. `CFG.muEdge = 0.10`, `j_n` = the normal impulse
  magnitude of the same event (so a separating/overlapping contact gets no friction).
- **Walls**: the tangential damping `wallTanKeep` is kept verbatim, but it now acts
  on the **contact point's** tangential speed `v_t = t̂·v − s·om·r` (`s = +1` on the
  low-coordinate wall, `−1` on the high one) and the same impulse carries the moment
  arm: `Δω = −s·2·Δv_t/r`. With `om = 0` this is algebraically identical to the old
  `v *= wallTanKeep`; a spinning puck can now rub spin into/out of its wall bounce,
  which is dissipative in the contact frame (work `= −m(1−k)·v_t²`).
- **Disk**: no impact model — the disk is flush with the floor (0.1.0 brief: a puck
  "moves onto" it), so the rim only ever *drags*, never bounces.

### 2.4 State machine touch-ups

- Lock (`a ≥ 0.999`, no relative slide at the centre, `ω²d ≤ μs·g`) **snaps the spin
  onto `ω_d`**: locking already snaps the velocity onto the surface, and a spin gate
  on top of it is wrong — measured, requiring `|ω_d − om| ≤ epsSpin` before locking
  pushes the capture behind the drift it is supposed to stop (a co-rotating puck at
  0.8 R drifts out to 1.25 R and the whole lock band collapses). The spin ramp only
  governs how a puck behaves *before* it is captured. Unlocking keeps the spin (a hit
  frees a puck that is still spinning) and the settle ramp drives `om` down with `ω_d`.
- Sleep additionally requires `|om| ≤ epsSpin` and snaps `om = 0`, so a puck that is
  still visibly spinning is not called stopped (it would otherwise sleep with 4 rad/s
  of spin on the clock).
- Sleep also accepts the **rim jam**: a puck at rest on the rim (both linear and
  angular velocity ~ 0) can be held by the floor patch when the covered share is the
  smaller one (`a ≤ 1−a` — both drags are μk), and the disk surface simply slides
  underneath it. Without that clause the puck is a zombie: `SLIDE`, `v = 0`, forever.
- `advance()` integrates `th += om·dt` for every non-sleeping puck; `recyclePucks`
  swaps `th`/`om` with the rest of the state.
- `CFG.epsSpin = 0.05` rad/s ≈ 5 mm/s of surface speed — the angular twin of the
  existing `epsSleep`.

## 3. Return rule: one fan, everything else removed

The draft names the shape: the zone that connects the disk centre to the two far
board corners, minus the disk. In board coordinates with `diskY = boardH/2` it is the
triangle `(diskX, diskY) – (boardW, 0) – (boardW, boardH)`:

```
(0,0)                                            (3.6,0)
  +-----------------------------------------------♦
  |        \                                      |  \
… the two lines run from the disk centre to the right-hand corners (the two far
      corners of the disk's side of the board), i.e. a ~48° fan across the whole
      thrower's side. Everything left of it — the shelf, the top/bottom lanes and
      the near corners — does not return.
```

- `RETURN_ZONES` becomes the three vertices (`ax, ay, bx, by, cx, cy`), and
  `inReturnZone` is the exact point-in-triangle test (three cross-product signs)
  plus the existing `onDisk` guard (`dist ≤ diskR + puckR`), which is what the draft
  means by "but not big_disk": a puck still touching the disk is in play no matter
  where its centre is (the fan contains the disk's right cap).
- Modes: `none` (classic, keep all) and `zones` (this fan) only — `behind` and the
  gutter cut-out are deleted, radio group shrinks to two options.
- Area: the fan is 2.75 m² of the 7.92 m² board (34.7 %) minus the trapezoid of the
  guard band along the disk edge → **30.5 % of the board** returns (measured on a
  600² grid), one contiguous shape with straight, readable edges. Gameplay reading:
  the fan *is* the ejection cone — a puck the disk flings back toward the thrower is
  a spent throw and is refunded, while anything the disk parks on the cold side (or
  that jams near the rim) stays and scores.
- Measured with the random bot (40 seeds, `experiments/zone-catch.js`): an a-priori
  death map (nothing ever recycled) puts **49 % of dead pucks in the fan**, 22 % on
  the left shelf and 29 % in the top/bottom lanes; playing the fan refunds **35 % of
  throws** (12.3 throws per round instead of 8.0) and still ends with a full board.

## 4. Rendering

- **Pucks**: 6 sectors, 3 of them shaded (`sectorPath`, unit radius, baked once),
  drawn under the existing ring/number in the puck's own `th`. The number shrinks to
  0.55 r and 0.75 alpha so the sectors read at a glance. Rotation is now the visible
  output of §2 (a puck riding the disk turns; a flung puck keeps turning and bleeds
  off; a cold puck never turns).
- **Zone**: the fan is filled with the existing teal, hatched, dashed-outlined, with
  the disk punched out as a **hole of radius `diskR + puckR`** (the exact guard
  boundary) using an `evenodd` fill — the on-disk exemption is now drawn, not just
  implied. Two rotated `RETURN` labels sit in the upper/lower lobes.
- The zone path is baked once in `buildZonePaths()` (with the board and the disk),
  never per frame; the spin needs no extra draw calls beyond one rotated fill.

## 5. Ghost preview refresh

`Game.invalidateGhost()` sets `ghostDirty`, and `ui.js` calls it from every physics
input: the ω / μk / μs sliders, `auto-ω`, and nothing else (the recycle radio
changes no physics). The re-sim stays throttled by `PRED_COOLDOWN = 0.08 s` and runs
in `Game.tick`, so sliders always leave a correct ghost on the next frame — also
while a bot is aiming, where only the *world* changed, not the chosen stroke.
