# Smartphone horizontal widescreen fit and top-space removal — 2026-11-19

## Review of previous rounds

Reviewed the standalone fit-to-screen pass (`archive/0.3-worklog.md`), the Snowfall minigame
adapter (`archive/0.5.4-worklog.md`), and the image-prompt pack (`img/prompts.md`):

- **`index.html` + `js/main.js` (`0.3`)**:
  1. `#app` used `height: 100vh; height: 100dvh;` in normal flow under `body { overflow: hidden }`.
     Whenever a smartphone browser kept its top URL/tab bar or bottom navigation bar visible in
     landscape (or lacked/lagged `100dvh`), `#app` stayed at the oversized large viewport height
     while `main.js`'s `visualViewport` listener only called `Render.resize()` without resizing
     `#app`, leaving the bottom of `<canvas>` clipped off-screen.
  2. `@media (max-width: 760px)` stacked `#panel` underneath `#boardWrap` (`flex-direction: column`)
     on width alone, hitting compact/360dp smartphones in horizontal widescreen (`568–760 px` wide,
     `280–360 px` tall).
  3. `#boardWrap` used `flex: 1 1 auto; align-items: center;` and `#app` kept `12 px` outer padding
     everywhere, inserting large vertical centering dead-space above `<canvas>` whenever width bound
     the board (`~60–180 px` on 16:9/4:3 desktop and notched landscape phones, `~100 px` above and
     below `<canvas>` on portrait phones).
  4. `js/render.js` `resize()` returned before updating `cv.style.width`/`height` if the capped
     device-pixel backing dimensions happened to round identically across two large CSS sizes.
- **`minigame/kerot.css` + `minigame/entry.js` (`0.5.4`)**:
  `.kerot-board-wrap` set `width: 100%; max-width: 760px; aspect-ratio: 3.6 / 2.2;` with no
  viewport-height bound, producing a `464 px`-tall canvas on `320–390 px`-tall horizontal
  smartphones, alongside ~`58 px` of header/padding above the board and reserved empty outcome
  paragraphs below the controls during live play.

## Implementation

- **`index.html`**:
  - Pinned `#app` with `position: fixed; top: 0; left: 0; right: 0; height: 100%; height: 100dvh;`
    (removing `100vh`) and reduced default top padding to `max(4px, env(safe-area-inset-top, 0px))`.
  - Changed `#boardWrap` to `flex: 1 1 0; align-items: flex-start; justify-content: center;` so
    vertical surplus never creates wasted blank space above `<canvas>`.
  - Added `@media (max-width: 960px), (max-height: 600px)` to strip `#app` padding/gap down to
    `2px`/`4px` (preserving safe-area insets) and narrow `#panel` to `clamp(188px, 28vw, 280px)` so
    horizontal widescreen smartphones keep the side-by-side row layout and give `<canvas>` almost
    100 % of visible height.
  - Scoped column stacking to `@media (orientation: portrait) and (max-width: 900px), (max-width:
    560px) and (min-height: 480px)` with `#boardWrap { flex: 0 0 auto; aspect-ratio: 3.6 / 2.2;
    max-height: 54%; }` and `#panel { flex: 1 1 0; }`, placing `<canvas>` flush at the top and
    handing all remaining height directly to `#panel`.
- **`js/main.js` & `js/render.js`**:
  - Added `syncAppBox()` in `js/main.js` to sync `#app.style.height` and `#app.style.top` to the
    live unzoomed `visualViewport` / `window.innerHeight` on boot, `resize`, `orientationchange`
    (including post-rotation frame/timeout settle), and `visualViewport` `resize`/`scroll`.
  - Updated `js/render.js` `resize()` to write `cv.style.width` and `cv.style.height` before the
    backing-store early return.
- **`minigame/kerot.css`, `minigame/entry.js`, `games/kerot.js`, `snowfall-demo.html`**:
  - Published `--kerot-vh` from `minigame/entry.js` (cleaned up on session teardown) and capped
    `.kerot-board-wrap` width by `calc((var(--kerot-vh, 100dvh) - …) * 3.6 / 2.2)`.
  - Reduced top padding/gaps above `.kerot-board-wrap`, hid `:empty` outcome notes during live play,
    added `@media (max-height: 560px)` compact horizontal-smartphone chrome so header + board +
    throw bar fit a single landscape screen, and rebuilt `games/kerot.js`.

## Next step suggestion

On smartphones in standalone `index.html`, `Throw ␣` and `Clear stroke` sit near the bottom of the
scrollable `#panel` below the physics sliders; making the action bar sticky at the top or bottom of
`#panel` on touch/small screens (`@media (hover: none), (max-height: 600px)`) would let touch
players throw without scrolling `#panel` first.
