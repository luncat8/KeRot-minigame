# 0.5.8 draft — review pass: loops, caches, fitted chrome and wording

User prompt for this round:

```
review game and fix issues and performance problems if found.
not about bot ballance because it is slow to test.
```

## Reading of the prompt

- **Review, not retune.** Bot profiles, search settings and win rates are out of scope; the
  round reads the frame loops, the browser layers, the shared caches and the text around
  the board for things that are wrong or cost work without buying anything.
- **A finding needs a gate.** Each fix below is covered by an existing smoke harness that
  can run without a browser, so the review does not add a second implementation or a new
  test framework.
- **Generated delivery stays in step.** Any change to `js/` used by the Snowfall adapter
  is rebuilt into `games/kerot.js` with `tools/build-minigame.js`.

## What was checked

- The fixed-step accumulator in `js/main.js` and `minigame/entry.js`, the input and
  restart gestures in `js/game.js`, the renderer's bake/resize paths, the score LUT,
  the vote caches, the game flow under live roster/setting edits, and the help/panel text.
- A 20k-frame headless fuzz over seat edits, speed rules, votes, pause, mass, schema,
  fit changes and resets: no NaN state, no owner index out of range, no puck over
  `MAX_PUCKS`, no stuck pending puck.
- `experiments/bench.js` (physics), `experiments/scoring.js` (score integration) and a
  predictor timing run: the hot sim is far below frame budget, so no physics rewrite was
  justified.

## Decisions

- **A resolved story match stops its own ticker.** `SnowfallGames` may keep the mount in
  the document after `answer()`; the adapter must not keep stepping and drawing a board
  whose canvas can already have been replaced by the result markup. `finished` joins the
  guards in `schedule()`; teardown remains the host's second cleanup path.
- **Floor fills belong to a renderer, not to the shared theme table.** They are made from
  a context and the current `boardH`; refitting changes `boardH`, so the fills are rebuilt
  with the zone paths on a geometry change.
- **The score LUT key includes the disk radius**, not only the schema: the grid is baked
  in disk-local metres, so its scale is part of what was baked. No behaviour changes at
  the shipped radius.
- **The resolve readout names the window, not the next seat.** Whether another turn
  follows depends on the return rule and the throw cap; a line that promises a seat can
  be wrong on the final throw.
- **Instructions match the gesture that shipped in 0.5.6**: aim from the ice outside the
  puck, tap the puck to throw.

## Rejected

- The vote profile was suspected of being cached under a schema key while the μ/mass
  sliders changed. It is baked from `puckRate` (the score map), not from friction, so the
  cache is correct for the inputs it uses; the change and its gate were reverted rather
  than left as a no-op "fix".
- Speeding up the standalone loop after `SCORED` was measured as noise against the
  settled board's already-tiny step cost; no throttle was added.
