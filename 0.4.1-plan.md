# 0.4.1 plan — presets, URL parameters, rim-schema bots, competition balance

Reference: `0.4.1-draft.md` (this round's user prompt and its reading).

## Part A — presets and URL parameters

- **`js/presets.js` (new, node-safe)** — the data and the mechanics, no DOM:
  - `PRESETS`: name → `{label, cfg?, schema?, recycle?, theme?, seats?, balls?, autoOmega?}`.
    cfg keys are CFG numbers; `autoOmega: true` re-solves the 90 % ω after the cfg
    values are set. Bundles: `default`, `slick`, `grippy`, `stones` (20 kg),
    `feathers` (0.5 kg), `grinder` (eject at ~0.3 R), `rimtrap` (rim6 schema),
    `solo` (human alone), and `bots` (six-bot league table).
  - `applyCfg(setup)` mutates CFG (numbers clamped to the slider ranges,
    μs ≥ μk kept). Theme, seats and the view toggles are the caller's.
  - `parseQuery(search)` → a plain setup object or null: keys `preset`, `omega`,
    `muk`, `mus`, `mass`, `schema`, `recycle`, `theme`, `seats` (comma list, seat
    types), `balls`, `ring`, `ghost`. Order inside applyQuery: named preset first,
    then individual keys override. Unknown keys ignored, numbers clamped; the page
    always boots.
  - `presetQuery(name)` is `preset=<name>`. The panel writes that (plus `ring`/`ghost`
    when those toggles are off). Boot does **not** rewrite the address bar: a link
    with overrides (`?preset=stones&omega=2`) must survive a refresh. A later manual
    control change replaces the query with the keys that differ from the shipped
    table, so the bar never keeps a preset the panel has left. Names are
    case-insensitive; seat lists are trimmed.
- **`js/game.js`** — `setSeatTypes(types)` replaces the roster wholesale and resets
  (table presets). Balls are `CFG.ballsPerPlayer`, dealt by that reset.
- **`js/ui.js`** — a "preset" select; choosing one applies the bundle through the
  same paths the individual controls use (setPuckMass / setDiskSchema / radios /
  theme select / roster), then `Game.reset()` and writes the preset's parameters
  into the URL. Any manual control change drops the select back to its placeholder.
  The controls are written from CFG on bind (`pullControls()`), so booting with
  parameters and the panel agree — today the sliders only show the HTML defaults.
- **`js/main.js`** — after `UI.bind`: `applySetup(parseQuery(location.search))`.
  No parameters → the call returns immediately, and boot is the page as shipped.
- **`index.html`** — the preset row + a help section documenting every key with an
  example link. Scripts include `js/presets.js` after `players.js`.
- **`experiments/client-smoke.js`** — stub `location`/`history`; gate: params apply
  and clamp, preset select lists the bundles, applying a preset sets CFG + controls
  + roster + resets, URL is rewritten, no-param boot is untouched.

## Part B — bots on the rim schema

The predictor already knows a capture from a fly-by. Two things kept the bots from using it:

- **Annuity** (`js/score.js` `stableRates`, `js/predict.js`, `js/bots.js`). Opportunity is the change in locked-or-asleep rate over the horizon still to come, not the rate at handoff. A puck on red at t = 4 s that is still sliding is followed only until *that* puck locks, sleeps, leaves, or 1.5 s pass. Score, recovery and losses stay the handoff window.
- **Feed grid**, not a jittered fifth group. From the launch lane the lock band is ~0.03 m/s wide and ~4° wide, on the co-rotating tangent, at about 0.90 of the floor-friction solve (that solve is fast: the disk drags less than the floor). Sample three hold-circle fractions (0.70, 0.82, 0.92 of d_hold) × three speed scales (0.86, 0.90, 0.94) × four angles (−1.5°…+3°), no jitter. One refine patch around the winner. The page shows a geometric aim during the think and searches once, at the throw.
- **Measure**: `bot-strategies.js` on classic, circles, rim6 — on rim6 the scoring profiles (keeper, hunter, balanced) must clear random. Classic and circles must not fall behind random either; their numbers may move, because the annuity fix changes every schema.

## Part C — 3-seat competition balance

- `experiments/matchup.js` (new): `node experiments/matchup.js [games] [seed0]
  seat0,seat1,seat2` — same rules as compete.js, plus a per-seat breakdown: raw
  score, seconds of puck-on-disk, mean rate while on it, locks at handoff, losses,
  returns. Uniform rosters give each profile's unopposed baseline; the mixed roster
  shows who actually pays whom.
- The 3-seat regression was the same annuity bug, not the weights: a fly-by and a
  lock priced the same, so keeper and hunter played the fly-by and random's noise
  won the variance. Do not retune profile weights to paper over that. The score
  model (red area × time) stays the game's rule.
- Re-run `compete.js` and commit the new row to `history.csv`.
